# 스킬: math-essay-item — 서·논술형 수학 문항 개발

위치 `~/.claude/skills/math-essay-item/`. 이번 프로젝트(중2 도형의 닮음 피자 문항)의 개발·검증 과정을 재사용 가능한 에이전트 파이프라인으로 굳힌 것.

## 파이프라인 (4단계 + 조판)
0. **입력** — 성취기준·평가 요소·총점·학년·시간을 AskUserQuestion으로 받는다(추측 금지).
1. **초안 3개 병렬** — 구매·의사결정 / 설계·제작 / 검수·판별 세 각도. 각 에이전트가 python으로 전 수치 재계산 + 학년 범위 위반 자체 검사. 심사 에이전트가 순위·개선점.
2. **사용자 선택** — 요약·수치 설계·전이성 판정·심사 의견을 표로 제시하고 고르게 함.
3. **채점 요소·급간 작성** — 개조식, 0점 없음, 문항 열에 성취기준 코드 병기.
4. **검증 세 겹** — 급간 게이트(적대적) + 어긋남 리뷰어(정합성) + Codex(필수). 지적 자체를 다시 적대적으로 재검증.
5. **HWPX 조판** — build_tpl2 → restyle → 고아 제거 → check_tpl2.

## 확정한 기본값
개조식 25~45자·50자 초과 금지 / 수행평가는 0점 급간 없음(모든 요소 2점 이상) / 전이성 5요건 전부 / NCIC 공시 성취수준 근거 / hwpx 조판까지 포함.

## 평가 유형 프로파일 분기 (2026-08-01)
사용자 확정 정책 — **0점 처리는 평가 유형을 따른다.** 근거는 연수 자료 자체다(수행평가 채점기준표 예시는 최저 1점, 정기시험 예시는 0점 "무응답 또는 그 외의 오답.").

| 항목 | 수행평가(기본값) | 지필평가(정기고사) |
|---|---|---|
| 최저 급간 | 1점 | 0점 |
| 0점 진술 | 없음 | `무응답 또는 그 외의 오답.` 고정 |
| 요소 최소 배점 | 2점 | 1점 |
| 급간 점수열 | s … 2, 1 | s … 1, 0 |
| 데이터 행 수 | 총점 | 총점 + 요소 수 = Σ(배점+1) |
| 제출자 최저 총점 | 요소 수 n | 0 |
| 성취수준 | 도달 가능 구간(n~총점) 재분할 | 0~총점 자연 분할 |

0단계에서 평가 유형을 묻고, 학교 학업성적관리규정이 프로파일과 다르면 규정이 우선한다. SKILL.md 원칙 2·0단계·3단계, rubric-rules §1~§7(PROFILE 분기 검사 코드), standards §4.2·4.3(check_levels floor 분기), failure-modes F02·F05·검증 프롬프트, hwpx-build R11~R13, verify-rubric.js, codex-review.md에 반영. 지필 E2E(26행 표) 조판·검증 통과 확인.

## Codex 4차 — 재검 감사 (2026-08-01)
3차 A급 5건의 **지정 반례는 전부 차단됨**을 실행으로 확인(그림 false-pass, `{...null}`, 오버라이드 6케이스, ㅁ받침 충돌, 성취수준 반례 4종). 그러나 "의미가 같은 다른 방향"의 우회가 새로 드러나 판정은 다시 **시행 보류**.

새 A급 3건:
1. **`_figs`를 아예 선언하지 않으면** 그림 3개가 빠진 최종 HWPX도 경고만 내고 PASS(exit 0). 예시 JSON 자체가 이 상태였다 — 자리표시 3개는 있는데 `_figs`도 `examples/figs/*.png`도 없다.
2. **`check_levels`의 bounds swap** — 이름 배열만 ABCDE로 두고 점수 구간을 A=0~7 … E=18~20으로 뒤집으면 여전히 True. 이름 swap은 막았지만 의미가 같은 수치 역전은 통과했다(원인: lo 기준 재정렬 후 연속성만 검사).
3. **examples-pizza B-6에 급간 중복 다수** — 한 답안이 2점과 1점에 동시에 걸리는 요소가 문항 1·2·3·4에 걸쳐 남아 있었다. "복제 가능"으로 표시된 블록이라 더 위험하다.

교훈 — **반례를 막는 것과 결함 유형을 막는 것은 다르다.** 3차에서 준 반례만 정확히 막으면 같은 결함이 다른 표현으로 살아남는다. 수선할 때 "이 반례가 통과하지 못하게" 대신 "이 부류가 통과하지 못하게"로 조건을 세워야 한다.

### 4라운드 수술 (2026-08-01)
Codex 4차 A급 3건 + B급 7건을 8갈래 병렬 수선, 회귀 136케이스 전량 통과.
- **그림 최종 모드** — `build_tpl2.py`·`check_tpl2.py`에 `--draft` 도입. **최종 모드가 기본값**이라 그림 파일이 없으면 빌드가 `FileNotFoundError`로 중단되고, `_figs`에 매핑되지 않은 `[그림 N]` 자리표시가 남으면 검증이 ERR로 차단한다. 초안 단계에서만 `--draft`로 자리표시를 허용한다. 예시 JSON에 `_figs`와 실제 PNG 3개(figlib 직접 작도, 정답 수치는 `?`)를 동봉해 예시 자체가 최종 게이트를 통과한다.
- **check_levels 방향 검사** — 이름만 ABCDE로 두고 점수를 뒤집는 bounds swap을 A 상한=총점·E 하한=0·A→E 내림차순 연속으로 차단. 지필 배분을 결정적 알고리즘(`C = ⌈(R+4)/5⌉` 먼저 고정)으로 확정해 "고르게 나눈다"와 "C가 유일 최대"의 충돌을 해소.
- **examples-pizza B-6 재작성** — 급간을 **'수행 개수' 한 축**으로 통일(4단 3/2/1/0개, 3단 3/1~2/0개). 2ⁿ 44벡터에서 겹침 0·공백 0 확인. 수정 전 문언은 겹침 14건이었다. A-6(다른 사례)은 겹침 1·공백 4가 남아 '결함·복제 금지'로 이동.
- **워크플로 `need` 헬퍼** — `{}`·필수 키 누락·빈 문자열·타입 위반 응답을 전부 throw. 감사가 통과시킨 반례 4종이 모두 차단됐다.
- **ATTEMPT 정규식** — ㅆ받침 과거 어간 + 부정 선행 차단자로 `했으나` 우회를 막고 `일부를`·`시도하지 못함` 오탐 0으로.
- **직접 수술 3건** — `build_tpl2`의 작업 트리 `out2/`를 산출물 옆으로(스킬 폴더 오염 차단), `figlib`의 데모 출력을 `FIGLIB_OUT`·현재 폴더 기준으로, **`check_tpl2`에 §5.6 BinData 정합 검사 신설**(고아·참조 누락·ZIP 누락을 ERR로 — 종전에는 4단계를 건너뛰어도 PASS였다).

## Codex 5차 + 뼈대 수술 (2026-08-01)
5차 판정 "시행 보류" — 4차 A급 3건은 반례 기준으로 고쳐졌으나 새 A급 4건.

1. **§3 급간 뼈대 자체의 결함** — 이것이 가장 컸다. 내부 진단(2ⁿ 전수 열거)이 Codex 주장을 확인했고, 결함은 4단만이 아니라 **전 단수**에 있었다.
   | 뼈대 | 겹침 | 공백 |
   |---|---|---|
   | 구 4단 | 1(백지가 2점·1점 동시) | 2(A 전무 + B 수행) |
   | 구 3단 | 0 | 1 |
   | 구 2단(문언 그대로) | 0 | 3 |
   | 구 지필 3점 사다리 | 2 | 0 |
   근본 원인은 **한 요소 안에 세 축이 섞인 것**이다 — 4점은 정오(`옳게`), 3점은 정오(`일부 오류`), 2점은 완성도(`일부만 수행`), 1점은 착수(`하지 못하고`). 문서 §4가 "축은 요소마다 하나"라고 정해 놓고 뼈대가 스스로 어겼다.
   **해결: '옳게 수행한 원자 수행의 개수' 한 축으로 통일.** 축을 고르는 규칙 9개(원자 먼저 확정, 수행 m ≥ s−1·지필 m ≥ s, 어휘는 `옳게 수행함`/`옳게 수행하지 못함` 한 쌍, 개수는 `만`·`도`로 못 박기, 2단 최저만 `한 가지 이상`)와 단수별 표를 새로 썼다. 대체 뼈대 10개 구성 전부 겹침 0·공백 0.
   부수 발견 — `두 가지를`은 '이상'으로 읽혀 8벡터 중 7벡터가 겹친다(`두 가지만`으로). 최고 급간을 산문으로 쓰면 `옳게`가 마지막 원자에만 걸린다(`모두 옳게`로).
2. **PNG가 서명만 검사됨** — IDAT·CRC·IEND가 없는 26바이트 껍데기가 조판·검증을 모두 통과했다. Pillow 없이 청크를 끝까지 걸으며 CRC까지 보는 구조 검증기를 `img_embed.py`에 넣고 빌더·검증기가 공유한다.
3. **`--draft`가 최종 게이트 우회** — 플래그 하나로 과거 A급 false-pass가 복원됐다. 완화를 쓴 실행은 `DRAFT-ONLY — 최종 제출 불가` + **종료 코드 2**를 내도록 바꿔 최종 성공(0)과 신호를 분리했다.
4. **out2가 사용자 폴더를 재귀 삭제** — 내가 직전 라운드에 만든 결함이다. 산출 폴더의 임의 `out2/`를 무조건 `rmtree`했고 같은 폴더 병렬 빌드끼리 서로를 지웠다. `tempfile.mkdtemp` 고유 트리 + `atexit` 정리로 교체. 사용자 파일 보존·병렬 2건 동시 성공·잔재 0을 확인했다.

**교훈** — 리팩토링이 결함을 만들 수 있다. 4번은 "스킬 폴더 오염"을 고치려다 "사용자 데이터 삭제"를 새로 심은 것이다. 오염 회피 같은 사소해 보이는 수정도 파괴적 연산(`rmtree`)을 건드리면 적대적 검증 대상이다.

### 뼈대 파급 (2026-08-01)
개수 축을 스킬 전체에 파급하고 회귀 10단계 중 9단계 통과, 마지막 문서 정합 실패분을 직접 수선했다.
- **예시 JSON 재작성** — 6요소의 원자를 발문·조건·예시답안에서 확정(4점 요소는 원자 4·4·3개, 3점은 3개, 2점은 2개 — 수행평가 하한 m ≥ s−1 충족). 급간 20행을 개수 축으로 다시 쓰고 원자 정의를 `_rubric_atoms_note`에 남겼다. **검사 15 경고 9건 → 0건.** 40벡터 전수 열거 겹침 0·공백 0. `partial`의 연쇄 오류 구제도 개수 축 어법으로("처음 틀린 수행 하나만 옳게 수행하지 못한 것으로 셈").

## Codex 6차 3갈래 + 타당도 수술 (2026-08-01)
6차는 한 번에 돌리다 컨텍스트 한도에 걸려 **코드·채점기준·문서 세 갈래로 나눠 병렬** 실행했다.

**문서 감사** — A급 2건. ① failure-modes F02 (ㄹ)이 "그 요건만 미충족이면 1점 급간"으로 **개수 축이 아닌 별도 축을 들여왔다**(3점 요소에서 하나만 틀리면 2점이 맞는데 1점으로 고정). ② transfer-and-numbers의 필수 검산 스크립트가 `Fraction` 미정의로 **NameError 중단** — "그대로 복사해 실행하라"는 지시가 실행 불가였다. 실패해도 종료 코드 0이던 것도 함께 고쳤다.

**채점기준 감사** — 급간의 겹침·공백은 0으로 재현 확인(예시 JSON 60벡터, B-6 44벡터, A-6 겹침 3·공백 22). 그러나 **채점 타당도**에서 시행 불가 판정:
- **연쇄 오류 중복 감점** — 원자가 서로의 입력인 구조(문항 1의 넓이→부피→관계)에서 한 번의 산술 오류가 세 원자를 무너뜨려 4점 중 2점이 된다. 구제 규정이 "앞 문항에서"로 **문항 사이만** 다뤄 같은 문항 안의 연쇄를 놓쳤다.
- **원자 정의 누락·은닉** — 조건이 요구한 필수 용어·첫 문장 위치·설득 대상이 원자 정의에 없고, 짧은 이름 뒤에 여러 산출이 숨었다.
반영: §3에 「연쇄 구조와 후속 오류」 신설(의존 그래프 필수 + 표준 구제 문장), 규칙 10(원자 독립성) 추가, 예시 JSON의 partial을 "앞 문항에서든 같은 문항 안에서든"으로 재작성하고 원자 정의에 필수 용어·범위·의존 그래프를 채웠다. failure-modes에 **F23(연쇄 증폭)·F24(정의 누락)·F25(복합 원자)** 신설 + 검증 프롬프트에 시험 13(타당도) 추가. §7 검사 15를 **경고에서 차단으로 격상**하고 `LEGACY_TABLE` 스위치를 뒀으며, 검사 16(원자 정의 정합)을 신설했다.
타당도 시나리오 검증 — 뿌리 오류 1개를 일관 전파한 답안 5종에서 구제 전/후가 2→3점, 1→3점, 1→2점으로 갈렸고 구제 후 개수가 전부 `m−1`이었다. 차원 혼동 답안에는 구제가 **불발**하는 것도 확인(원자 정의가 계산식을 요구하므로).

**코드 감사** — 실제 결함 5건 전부 수선:
① PNG가 IDAT 압축 해제·IEND 뒤 잉여를 안 봐 **열 수 없는 파일이 통과** → zlib 해제 확인 + 잉여 바이트 거부. ② **자리표시가 문장 중간에 있으면 놓쳤다**(`re.match`가 줄머리만) → `finditer`. ③ 같은 이름 동시 빌드로 **손상 zip** 가능 → 임시 파일 + `os.replace` 원자적 공개(동시 3건 실행에서 zip 무결 확인). ④ §5.6이 ZIP에만 있는 파일·중복 등록·`_figs` 밖 손상 payload를 놓침 → 전부 오류로. ⑤ **빌더가 서식의 미참조 이미지를 아예 넣지 않도록** 바꿔 수동 "고아 제거" 단계를 없앴다 — 조판이 build → restyle → check **세 단계**가 됐다.

**교훈** — 형식 검증(겹침·공백 0)을 통과해도 **타당도**는 별개다. 개수 축은 배타성 문제를 풀었지만 감점 비례성이라는 새 문제를 만들었고, 그것은 2ⁿ 열거로는 절대 드러나지 않았다. 적대적 검증을 형식과 내용 두 층으로 나눠 물어야 한다.
