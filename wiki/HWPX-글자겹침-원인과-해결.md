# HWPX 글자 겹침 — 원인과 해결

템플릿 HWPX의 표 칸에 긴 문단을 채워 넣으면, 한글 뷰어에서 **문단의 모든 글자가 한 줄에 겹쳐
검은 막대처럼** 보인다. 한 줄에 들어가는 짧은 문단은 정상이다. 원인은 두 가지가 겹쳐 있었고
둘 다 고쳐야 한다.

## 원인 1 (근본) — 셀의 `lineWrap="SQUEEZE"`

표 칸의 `<hp:subList>`에는 `lineWrap` 속성이 있다.

- `SQUEEZE` = **자간을 조종하여 한 줄을 유지**. 그 칸은 자동 줄바꿈을 하지 않는다.
- `BREAK` = 정상적으로 줄을 나눈다.

빈 서식 템플릿의 칸은 대부분 `SQUEEZE`다(한 줄짜리 라벨을 담도록 만들어졌기 때문). 이 상태로
긴 텍스트를 넣으면 한글은 자간을 줄여 한 줄에 밀어 넣으려 하고, 결과가 겹친 검은 막대다.
**linesegarray를 아무리 정확히 넣어도, 한글 데스크톱이 재계산해도 고쳐지지 않는다.**

전수 근거: 로컬의 한글 저작 HWPX 342개에서 `SQUEEZE` 문단 14,766개 중 다중 줄은 26개뿐이고
그 26개는 전부 `<hp:lineBreak/>` 강제 개행이다(자동 줄바꿈 0건). `BREAK`는 66,053개 중
4,327개(6.6%)가 다중 줄이다.

→ **내용을 채우는 칸은 `lineWrap`을 `BREAK`로 바꾼다.** 한 줄짜리 라벨 칸은 `SQUEEZE`로 둬도 된다.

## 원인 2 — `linesegarray`가 문단당 1개

`<hp:linesegarray>`는 **캐시된 줄 배치**이며 `<hp:lineseg>` 하나가 렌더링 줄 하나다.
문단당 1개만 넣으면, 캐시를 신뢰하는 뷰어는 문단 전체를 한 줄로 그린다.

→ **실제 줄 수만큼 lineseg를 생성한다.**

## lineseg 작성 규격 (템플릿 역산 + 342개 파일 전수 검증)

```
vertsize = textheight = charPr.height              # 12pt → 1200
baseline = round(vertsize × 0.85)                  # 1200 → 1020
spacing  = round(charPr.height × (lineSpacing% − 100) / 100)
pitch    = vertsize + spacing
textpos  = 그 줄이 시작하는 문자 인덱스 (문단 내 0-based)
vertpos  = 셀 안에서 누적       ← 문단마다 0으로 리셋하지 않는다
horzpos  = 0
flags    = 393216
horzsize = 그 셀에 한글이 이미 써 둔 lineseg의 horzsize를 그대로 재사용
```

> **함정 1** — `vertpos`는 문단이 아니라 **셀(subList) 전체에서 누적**된다.
> 문단마다 0에서 시작하면 49문단짜리 칸의 모든 문단이 같은 자리에 겹친다.
> 근거: 원본 템플릿 T4의 2문단 칸(paraPr 71, pitch 1560)의 vertpos가 0, 1560.
>
> **함정 2** — `horzsize`를 `셀너비 − 좌여백 − 우여백`으로 계산하면 안 된다.
> 9개 셀 폭 중 5개에서 1~3 HWPUNIT 어긋난다(예: 10407−1020=9387이나 실제 9384).
>
> **함정 3** — 한 쪽보다 큰 표 다음 문단의 vertpos를 0으로 리셋하면 안 된다.
> 표는 마지막 쪽에서 `(전체높이 mod 쪽가용높이)`만큼 자리를 차지한다.
> 리셋하면 뒤따르는 제목이 표 꼬리 위에 얹힌다(이 문서에서 35,028 HWPUNIT ≈ 4.9cm 겹침).
> `page += span // usable; cursor = span % usable` 로 이어가야 한다.

## 문자 폭 모델 (12pt 맑은 고딕, em = 1200 HWPUNIT)

| 분류 | 폭 |
|---|---|
| 결합 문자 (`unicodedata.combining != 0`, 예: U+0307 — 0.83̇의 점) | **0** |
| 전각 W/F — 한글·한자·〔〕〈〉【】·㉮㉠·U+3000 | 1200 |
| 모호 A — · — → ÷ … ※ × ³ ○ ① ⓐ ⑴ Ⅰ | 1200 (보수적) |
| 반각 알파벳 | 840 |
| 반각 숫자·부호 | 720 |
| 공백 | 600 |

**보수적으로(넓게) 잡는 것이 핵심이다.** 과대추정하면 줄이 조금 일찍 끊겨 짧아질 뿐이지만,
과소추정하면 줄이 칸 밖으로 넘쳐 겹침이 재발한다.

정답 대조: 원본 템플릿의 다중 lineseg 문단 2건을 이 모델로 정확히 재현한다.
`'서·논술형 평가 문항 재구성'`@9388 → textpos [0, 9] / `'채점 기준 초안'`@4184 → [0, 3, 6].

## 그 밖에 함께 고친 것

- `charPrIDRef` 58 → **59**. 58은 같은 스타일에 `<hh:bold/>`가 붙어 있어 본문이 전부 굵게 나왔다.
- 왼쪽 정렬 본문 칸의 `paraPrIDRef` 73 → **14**. 73은 문단마다 `margin.prev=700`을 넣어
  빈 문단과 겹쳐 간격이 이중이 되고, 120%인 lineSpacing이 하드코딩된 spacing 720과 모순이었다.
  14는 JUSTIFY 130%, prev/next/intent 모두 0.
- 셀·행·표 높이를 `여백(top+bottom) + Σ(줄수 × pitch)`로 다시 계산하고,
  같은 행의 형제 셀과 rowSpan 셀, 표 전체 높이를 함께 맞춘다.
