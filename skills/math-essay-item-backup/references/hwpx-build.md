### 1단계 — 슬롯 JSON 작성

`$WORK/content.json`. 키 목록은 2절, 값 형식 규칙은 5절.

### 2단계 — build_tpl2.py

```bash
cd "$WORK" && python3 build_tpl2.py "출력파일.hwpx" content.json
```

인자는 **출력 경로가 먼저, 콘텐츠 JSON이 나중**이다. 마지막 두 줄을 확인한다.

```
wrote 출력파일.hwpx

== 자체 점검 ==
   lineseg 920개, SQUEEZE 다중줄 위반 0건
```

`SQUEEZE 다중줄 위반`이 0이 아니면 여기서 멈춘다. 이 단계에서 남은 위반은 이후 단계에서 사라지지 않는다. 원인은 사실상 하나다 — **여러 줄이 되는 값을 줄바꿈 문자를 넣은 문자열 하나로 넘겼다**(5절 R18, 6절 F4). 해당 슬롯을 줄 단위 배열로 바꾸고 2단계를 다시 돌린다.

### 3단계 — restyle.py

```bash
cd "$WORK" && python3 restyle.py "출력파일.hwpx"
```

`.hwpx`를 제자리에서 다시 쓴다. 출력 예:

```
treatAsChar 해제 9건 / 라벨 셀 재작성 52건 (함초롬바탕 11pt, T0 제외)
```

`treatAsChar 해제`가 0이면 표가 '글자처럼 취급'으로 남아 페이지 넘김이 어긋난다.

### 4단계 — 검증 (`check_tpl2.py`)

**고아 BinData 제거 단계는 없어졌다.** 빌더가 서식 원본의 미참조 이미지(예시용 말풍선 `image1.bmp`·`image2.bmp`)를 산출물에 넣지 않고 `미참조 BinData 제외: [...]`로 알린다. 남은 이상은 검증기 §5.6이 오류로 잡는다 — 고아, 참조되나 매니페스트에 없음, 매니페스트에 있으나 ZIP에 없음, ZIP에 있으나 매니페스트에 없음, id·href 중복, 등록된 PNG의 구조 손상.

```
### 5.6 BinData 정합
  고아 0건 / 참조 누락 0건 (등록 3개, 참조 3개)
```

**R3.** zip을 다시 쓸 때 `mimetype`을 **첫 엔트리·무압축(ZIP_STORED)**으로 넣는다. 이 규칙을 어기면 한글이 파일을 열지 못한다. 검증기 `### 1. XML / ZIP`이 이것을 본다. 빌더는 임시 파일에 다 쓴 뒤 `os.replace`로 자리를 바꾸므로, 같은 이름으로 동시에 빌드해도 반쯤 쓰인 파일이 남지 않는다.

#### 실행

```bash
cd "$WORK" && python3 check_tpl2.py "출력파일.hwpx" content.json
```

**R4.** 콘텐츠 JSON을 두 번째 인자로 **반드시** 넘긴다. 생략하면 스크립트 폴더의 기본 파일을 찾다가 없으면 `[ERR]`로 집계되어 FAIL한다(내용 보존을 검사하지 못했으므로) — 조용히 건너뛰지 않는다.

## 3. 특수 키

밑줄로 시작하는 키는 칸이 아니라 빌더의 동작을 바꾼다. 검증기의 내용 보존 검사에서도 제외된다.

### `_flat_cond` (불리언)

```json
"_flat_cond": true
```

참이면 `build_cond_v4()`가 조건 상자를 찾아 **1행 1열 표**로 다시 만들고 `〈조 건〉`과 조건 본문을 문단으로 이어 넣는다. 표는 인덱스가 아니라 내용으로 찾는다(본문에 `조건`이 있고 여는 태그가 `colCnt="5"`인 표).

`_flat_cond`가 없으면 `item_cond`가 (8,1,2) 칸 하나에만 들어가고 장식용 빈 셀 7개가 그대로 남아 **빈 상자들이 함께 인쇄된다.** 조건 상자를 쓰면 항상 `true`로 둔다.

### `_check_class` (문자열)

```json
"_check_class": "3분반"
```

`check_class_box()`가 분반(교과) 칸을 찾아 그 라벨 **바로 앞**의 `<hp:checkBtn>`을 `value="UNCHECKED"` → `"CHECKED"`로 바꾼다. 값은 서식에 있는 라벨과 글자가 정확히 같아야 한다(`1분반`·`2분반`·`3분반`·`4분반`·`5분반`). 성공하면 로그에 `체크박스 선택: 3분반 (CheckBox5)`가 찍힌다.

### `_figs` (객체)

```json
"_figs": { "[그림 1]": ["fig8", "figs/fig8_boxes.png"] }
```

`{자리표시 문자열: [BinData id, PNG 경로]}`. **그림을 하나라도 쓰면 쓰는 그림 전부를 `_figs`에 적는다.** 생략하면 `build_tpl2.py`의 기본 `FIGS`(`[그림 1]`→fig1, `[그림 2]`→fig5, `[그림 3]`→fig6)로 조용히 대체되고, 검증기 5.5 그림 게이트도 `_figs`가 있을 때만 도므로 그림이 빠진 산출물이 그대로 PASS로 나온다. 기본값과 같은 매핑이라도 명시적으로 적는다 — 예시 파일도 세 그림을 다 적어 둔다. 본문(`item_intro`)의 한 줄이 자리표시 문자열로 **시작**하면 그 줄을 그림 문단으로 바꾸고, **자리표시 줄 자체를 캡션 문단으로 한 번 더** 넣는다. 그래서 본문에는 `[그림 1] 세 가지 크기의 피자 (실제 지름 비율)` 한 줄만 쓰면 그림과 캡션이 함께 생긴다.

### `_alignment_note` (문자열)

```json
"_alignment_note": "std1_A의 '부피의 비를 추론할 수 있으며' → 문항 1·2 …"
```

빌더가 **소비하지 않는 주석 키**다. 성취기준의 어느 문구가 어느 문항·채점 요소로 갔는지 정렬 근거를 슬롯 JSON 안에 남겨 두는 용도이며, 조판 결과에는 아무 영향이 없다. `_` 접두라서 5절 내용 보존 검사에서도 제외된다 — 즉 여기 적은 문장은 지면에 인쇄되지 않고, 인쇄되지 않았다고 `누락 줄`로 잡히지도 않는다.

## 4. rubric_rows 형식

```json
"rubric_rows": [
  {
    "item": "문항 1\n[9수03-12]\n닮음비와 넓이·부피의 비 구하기",
    "elem": "세 비 구하고 관계 설명하기",
    "score": "4",
    "desc": "세 피자의 지름·넓이·부피의 비를 옳게 구하고 그 관계를 옳게 설명함."
  },
  { "item": "문항 1\n[9수03-12]\n닮음비와 넓이·부피의 비 구하기",
    "elem": "세 비 구하고 관계 설명하기", "score": "3",
    "desc": "지름의 비·넓이의 비·부피의 비·관계 설명 가운데 세 가지만 옳게 수행함." },
  ...
  { "item": "합계", "elem": "—", "score": "20점",
    "desc": "문항 1부터 문항 4까지의 점수를 합하여 20점 만점으로 함." }
]
```

**한 급간 = 배열 원소 1개 = 표 1행.** 네 필드가 표의 네 열에 그대로 대응한다.

| 필드 | 열 | 내용 |
|---|---|---|
| `item` | 문항 | 문항 번호 / 성취기준 코드 / 그 문항의 평가 요소 — `\n`으로 나눈 **세 줄** |
| `elem` | 평가요소(채점요소) | 채점 요소 이름. 명사구 |
| `score` | 배점 | 그 급간의 점수. 숫자 문자열 |
| `desc` | 수행 특성(채점 기준) | 그 급간의 수행 진술 |

### 세로 병합

`build_rubric_v2()`가 **연속한 원소에서 값이 같으면 자동으로 rowSpan으로 묶는다.** 표에 병합 지시를 따로 쓰지 않는다.

- `item`이 같은 연속 원소 → 문항 열이 그만큼 세로 병합
- `elem`이 같은 연속 원소 → 평가요소 열이 그만큼 세로 병합

**R9.** 같은 문항의 급간은 배열에서 **반드시 연속**해야 한다. 문항 1 → 문항 2 → 문항 1처럼 흩어 놓으면 병합이 세 조각으로 쪼개진다.

**R10.** `item` 문자열은 세 줄 모두 글자가 완전히 같아야 병합된다. 한 글자라도 다르면 다른 문항으로 본다.

### 검사 가능한 작성 규칙

**R11.** 한 채점 요소의 `score`는 그 요소의 배점부터 **평가 유형 프로파일의 최저 급간**(수행평가 1점, 지필평가 0점 — `references/rubric-rules.md` §2)까지 **1씩 하강**한다. 건너뛰지 않는다.
`4 → 3 → 2 → 1` (수행평가 ○) / `4 → 2 → 1` (×, 건너뜀) / `2 → 1 → 0` (수행평가 ×·R12, 지필평가 ○)

**R12.** 수행평가 채점기준표에는 **0점 급간을 두지 않는다.** 최저 급간은 1점이다(이 스킬의 확정 정책 — 경기 2025 원문에는 0점 급간 표와 없는 표가 혼재하므로 외부 근거가 아니다. `references/rubric-rules.md` §2가 권위다). 0점을 지워 급간이 한 단만 남는 요소는 다른 요소와 **통합**한다. v5에서 요소 9개를 6개로 합쳤고 v6도 그 6개를 그대로 쓴다. 지필평가(정기고사) 채점기준표는 반대로 **요소마다 0점 급간을 두고** 진술을 `무응답 또는 그 외의 오답.`으로 고정하며, 1점 요소를 허용한다 — 데이터 행 수가 총점 + 요소 수가 된다.

**R13.** 최저 급간은 **시도를 전제하지 않는다**(두 프로파일 공통). 시도를 전제하면 그 진술이 상위 급간의 상태까지 삼켜 배타성이 깨진다. 술어는 `옳게 수행하지 못함`·`옳게 구하지 못함`처럼 **`옳게`를 넣은 부정형**이어야 한다 — `하지 못함`만 쓰면 착수 여부를 재는 축이 되어 틀리게라도 손댄 답안의 귀속이 정해지지 않는다. 지필평가는 백지·무응답이 0점 급간으로 가므로 이 규칙을 1점 급간에 적용하지 않는다(`references/rubric-rules.md` §3).

최저 급간의 접속을 고르는 규칙은 **폐기됐다**(rubric-rules §3). 개수 축에서는 최저 급간이 `한 가지도 옳게 수행하지 못함`(= 0개) 하나로 고정되어 고를 자리가 없다. 예외는 2단 최저 급간뿐이고, 이접형으로 쓸 때는 두 이접지에 모두 `옳게`를 넣는다.

- 나쁨: `㉠의 잘못을 밝히려 하였으나 근거가 타당하지 않음.` (`밝히려 하였으나`가 시도를 전제)
- 나쁨: `공지문의 일부를 옳게 구하지 못함.` (`일부를`이 부분 수행을 전제)
- 좋음(4단, 원자 3개): `부피 산출, 단위량당 값, 두 단계 판단 가운데 한 가지도 옳게 수행하지 못함.`
- 좋음(3단, 원자 3개): `㉠ 반박, 세 문단 구성, 문단별 내용 가운데 한 가지도 옳게 수행하지 못함.`
- △ 구 뼈대(쓰지 않는다): `필요한 부피와 세 방안의 값을 구하지 못하고 방안도 판단하지 못함.` / `㉠의 잘못을 반박하지 못하고 공지문도 쓰지 못함.` — `옳게`가 없어 착수 축이다.

**R14.** `desc`는 마침표로 끝나는 **한 문장**이고(마침표는 문장 끝 1개뿐), **25~45자**로 쓰며 **50자를 넘기면 차단**이다. 종결은 명사형 어미(받침 ㅁ) — `~함.` `~있음.` `~못함.`. v6 실측 27~42자, 중앙 38자.

- 나쁨(v2 실물, 200자 초과): `⑴⑵⑶을 모두 옳게 수행한 경우. ⑴ 세 피자의 지름의 비를 4 : 5 : 6으로 나타냄. ⑵ 세 피자의 윗면 넓이를 144π·225π·324π cm²로 구하고 윗면 넓이의 비를 16 : 25 : 36으로 나타냄. ⑶ …`
- 좋음(v6, 39자): `세 피자의 지름·넓이·부피의 비를 옳게 구하고 그 관계를 옳게 설명함.`

**R15.** 급간 뼈대는 `references/rubric-rules.md` §3 「급간 뼈대」를 따른다 — 축은 **옳게 수행한 원자 수행의 개수** 하나이고 술어는 `옳게 수행함` / `옳게 수행하지 못함` 한 쌍이다. `일부 오류`·`일부만 수행`은 축을 섞으므로 급간에 쓰지 않는다. 아래 세 가지는 **0건**이어야 한다 — `⑴⑵⑶` 하위 요건 나열, `[채점 요소 N]`·`원칙 N`·`〈조 건〉N` 같은 문서 내부 참조, 그리고 모호어 `미흡`·`부족`·`다소`·`대체로`·`적절히`·`적절하게`·`충분히`·`어느 정도`·`나름대로`(rubric-rules §7 검사 10의 목록과 같다).

- 나쁨: `[채점 요소 1] 윗면 넓이·부피와 세 비의 산출 [2점]` (elem에 배점·번호를 넣음)
- 좋음: `세 비 구하고 관계 설명하기` (elem은 `~하기`로 끝나는 명사구, **6~16자**. v6 실측 13~15자)

**R16.** `item` 셋째 줄의 평가 요소는 10~17자로 축약한다. 2025 경기 자료의 평가 요소 길이에 맞춘다. 자수는 공백 포함 `len()`으로 센다.
`닮음비와 넓이·부피의 비 구하기`(17) / `판 수 구하고 새 규격 설계하기`(17) / `윗면 넓이의 비로 개수 정하기`(15)
축약 전 v4의 `닮음비와 넓이의 비·부피의 비 구하기`는 20자라 표에서 세 줄로 접혔다.

**R17.** 마지막 원소는 합계 행이다. `item`은 `"합계"`, `elem`은 `"—"`, `score`는 `"20점"`처럼 단위를 붙인다. `score`의 숫자 합이 문항별 배점 합, 발문에 적은 배점, 도입부 총점, 성취수준 최고 구간과 모두 일치해야 한다.

## 5. 값 형식 규칙

**R18. 여러 줄이 되는 값은 반드시 줄 단위 배열로 넘긴다.** 줄바꿈 문자를 넣은 문자열 하나로 넘기지 않는다.

빌더는 배열의 원소 하나를 문단 하나로 만들고, 문단마다 `metrics.wrap()`으로 줄 수를 세어 `<hp:lineseg>` 캐시를 만들고, 그 줄 수를 합해 셀 높이를 키운다. 문자열 하나로 넘기면 문단이 하나뿐이라 개조식 줄이 한 문단으로 뭉치고, 셀 높이도 한 문단분만 잡혀 **글자가 한 줄에 겹쳐 인쇄된다.**

- 나쁨: `"item_cond": "① 윗면 넓이는 …\n② 문항 3에서는 …\n③ 문항 2에서 …"`
- 좋음:
  ```json
  "item_cond": [
    "【해결 방법의 제한】",
    "",
    "① 윗면 넓이는 반드시 원의 넓이 공식 …으로 구하고, 계산한 식을 답안에 남길 것.",
    "",
    "② 문항 3에서는 판단의 근거로 다음 (ㄱ)·(ㄴ)·(ㄷ)의 값을 모두 구할 것.",
    "　(ㄱ) 부원 8명에게 필요한 부피"
  ]
  ```

**R19.** 빈 줄은 `""` 원소로 넣는다. 빈 문자열은 빈 `<hp:run>` 한 개짜리 문단이 되어 줄 하나 높이를 정상적으로 차지한다.

**R20.** 줄바꿈 문자 `\n`은 **`rubric_rows`의 셀 값에서만** 쓴다(`item`의 세 줄). `_cell_paras()`가 `\n`으로 쪼개 문단을 만든다. 다른 슬롯에서는 쓰지 않는다.

**R21.** 들여쓰기는 공백이 아니라 전각 공백 `　`(U+3000)으로 준다. `metrics.py`가 전각 공백을 1em으로 세므로 줄바꿈 계산이 맞는다. 반각 공백은 0.5em이라 어긋난다.

**R22.** 내어쓰기 서식은 문단 첫 글자로 자동 판별된다(`hang_style()`). 규칙에 맞는 글머리만 쓴다.

| 첫 글자 패턴 | 적용 서식 |
|---|---|
| `문항 1.` `(1)` `㉮㉯㉰㉱` | 발문용 — 내어쓰기 1308, 줄간격 120 % |
| `①`~`⑧`, `(ㄱ)`~`(ㄹ)`, `·` `•` | 조건용 — 내어쓰기 2100, 줄간격 140 % |

자동 판별이 도는 슬롯은 `item_questions`와 `item_cond` 두 개뿐이다.

## 6. 함정 목록

이번 개발에서 실제로 겪은 것만 적는다.

### F1. 표 인덱스는 채우는 도중 바뀐다 — 표는 내용으로 찾아라

`surgery_4items()`가 T3에 행을 넣고 T9에 두 행을 넣고 T10의 rowSpan을 푸는 순간, 그 뒤 표들의 XML 위치가 밀린다. `build_cond_v4()`·`build_rubric_v2()`가 뒤에 도는데 고정 인덱스를 쓰면 엉뚱한 표를 뜯는다.

- 나쁨: `a, b = all_tbl_spans(xml)[10]`
- 좋음: `find_rubric_tbl()` — 여는 태그가 `colCnt="4"`이면서 본문에 `수행 특성`과 `평가요소`가 모두 있는 표를 찾는다.
- 좋음: `build_cond_v4()` — 본문에 `조건`이 있고 여는 태그가 `colCnt="5"`인 표를 찾는다.
- 좋음: `check_class_box()` — `1분반`과 `<hp:checkBtn`을 함께 갖고 길이가 12000자 미만인 `hp:tc`를 찾는다.

칸 채우기도 같은 이유로 **문서 뒤쪽부터** 처리하고, 칸마다 `get_cell()`로 좌표를 다시 구한다. `build_tpl2.py` 파일 상단의 `RUB_TBL = 10`은 남아 있는 상수일 뿐 실제로 쓰이지 않는다. 새 코드에서 참조하지 마라.

### F2. 데이터 행 rowAddr이 헤더와 겹쳐 셀 주소가 중복된다

채점기준표를 다시 만들 때 헤더 행이 `rowAddr="0"`을 차지하고 있다. 데이터 행 `rows[0]`을 그대로 `rowAddr="0"`으로 쓰면 헤더와 주소가 겹쳐 한글이 표를 깨진 것으로 읽는다.

- 나쁨: `CELL_TPL.format(..., row=r, ...)`
- 좋음: `CELL_TPL.format(..., row=r + 1, ...)`

검증기 `### 2. 표 격자`가 `[ERR] T10 cellAddr 중복 ('0', '0')`으로 잡는다. 통과 기준은 **중복 0건**이다.

### F3. 문단 모양에 문단 테두리가 붙어 문단마다 상자가 그려진다

### F4. 값을 줄바꿈 문자열로 넘기면 글자가 겹친다

5절 R18과 같은 사고다. 증상이 두 갈래로 나온다.

1. 개조식 줄이 한 문단으로 뭉쳐 `① … ② … ③ …`이 한 덩어리로 흐른다.
2. 셀 높이가 한 문단분만 잡혀 **한 줄 자리에 여러 줄이 겹쳐 찍힌다.**

두 번째가 특히 위험한 이유는 칸의 `lineWrap`이 `SQUEEZE`(자동 줄바꿈 안 함)일 때 한글이 자동 재배치를 하지 않아 파일을 열어도 겹친 채로 보이기 때문이다. 빌더는 채우는 칸의 `lineWrap="SQUEEZE"`를 `"BREAK"`로 바꾸지만, 여러 줄을 문단 하나에 밀어 넣으면 그래도 캐시가 어긋난다. **반드시 줄 단위 배열로 넘긴다.**

### F5. 표 안 글꼴 통일과 줄바꿈 캐시 재계산은 빌드 뒤에 한 번 더 해야 한다

`build_tpl2.py`는 자기가 **채운 칸만** 함초롬바탕 11pt(`CID_N`/`CID_B`)로 쓴다. 서식이 원래 갖고 있던 라벨 셀(`학교급`, `평가 과제`, `성취수준` …)은 원본 글꼴 그대로 남아 표 안에 두 글꼴이 섞인다. 그리고 글꼴을 바꾸면 글자 폭이 바뀌므로 **줄바꿈 캐시(`<hp:lineseg>`)를 다시 계산해야** 한다. 그러지 않으면 캐시된 줄 길이가 실제 폭과 어긋나 셀 밖으로 넘친다.

`restyle.py`가 이 둘을 함께 한다: 라벨 셀을 통일 charPr로 다시 쓰고 `metrics.wrap()`으로 lineseg를 다시 만든다. 그다음 표 안(T0 문서 제목 표 제외)의 남은 `charPrIDRef`를 일괄 치환한다(빈 run·그림 run 포함).

**R24.** `restyle.py`는 통일 charPr을 **header.xml의 마지막 두 `charPr` id**로 가정한다.
```python
ids = sorted(int(m) for m in re.findall(r'<hh:charPr id="(\d+)"', hdr))
CID_N, CID_B = str(ids[-2]), str(ids[-1])
```
빌드 뒤 `header.xml`에 `charPr`을 더 붙이면 restyle이 엉뚱한 id를 통일 글꼴로 쓴다. 순서를 지켜 빌드 직후에 돌린다.

**R25.** `metrics.py`의 프로파일을 바꾸지 않는다. 빌더와 restyle 양쪽이 같은 설정을 쓴다.
```python
MT.use_profile('conservative')
MT.HANGABLE = frozenset()
```
`conservative`는 애매한 폭(`·`, `※`, `①`)을 1em으로 잡아 캐시된 줄을 실제보다 **짧게** 만든다. 짧은 줄은 그냥 여백이 남지만 긴 줄은 셀 밖으로 넘친다. 안전한 방향이 정해져 있다.

### F6. 표 '글자처럼 취급'을 풀어야 한다

## 7. 검증 통과 기준

`python3 check_tpl2.py "출력파일.hwpx" content.json`의 출력을 항목별로 본다.

| # | 검사 | 통과 기준 |
|---|---|---|
| 1 | XML / ZIP | 모든 `.xml`·`.hpf`·`.rdf`가 `ET.fromstring()`으로 파싱된다. `[ERR]` 0건. 첫 엔트리가 `mimetype`이고 `method=0`. `testzip=None` |
| 2 | 표 격자 | 모든 표에서 `span합 == rowCnt×colCnt` (`OK`). **`cellAddr 중복` 0건** |
| 3 | 스타일 참조 | `미정의 paraPr: []`, `미정의 charPr: []`, `미정의 borderFill: []` — 셋 다 빈 목록 |
| 4 | lineWrap / 겹침 | **`SQUEEZE 칸 다중줄 문단: 0건`**, `[ERR] textpos 이상` 0건. 표내 charPr 통일과 표 밖 문단 세로 겹침도 이 단계에서 자동 검사된다 — 둘 다 오류 0건 |
| 5 | 내용 보존 | **`누락 줄: 0`**. 콘텐츠 JSON을 찾지 못하면 `[ERR]`로 집계되어 FAIL한다(R4) |
| 5.6 | BinData 정합 | `고아 0건 / 참조 누락 0건 (등록 N개, 참조 N개)` 한 줄만 나온다. **고아**(아무도 참조하지 않음)·**참조되나 매니페스트에 없음**·**매니페스트에 있으나 ZIP에 없음** 셋을 각각 `[ERR]`로 집계한다 |

**통과 기준** — `check_tpl2.py`는 PASS/FAIL을 출력하고 종료 코드 0/1을 반환한다. **PASS가 아니면 조판 실패로 처리한다.** 서식 원본 유래 폭 초과 1건은 허용 경고로 분류되어 오류에 들어가지 않는다.

**고아 BinData는 이제 PASS 조건 안에 있다.** 예전에는 검증기에 §5.6이 없어 고아가 남아도 PASS가 나왔고 4단계 수동 확인이 유일한 방어선이었다. 지금은 §5.6이 고아를 `[ERR]`로 집계하므로 **4단계를 건너뛴 산출물은 PASS를 받지 못한다.** 다만 검증기는 탐지만 하고 제거하지는 않으므로 4단계의 제거 스크립트 자체는 계속 필요하다(R32).

```
### 5.6 BinData 정합
  고아 0건 / 참조 누락 0건 (등록 3개, 참조 3개)
…
============================================================
PASS — 오류 0건 / 경고 1건
```

**허용 경고 1건의 정체** — 서식이 원래 갖고 있는 표 바깥 안내 문단 하나가 `1줄 캐시인데 폭 초과`로 잡힌다.

```
※ 평가 유형(지필평가, 수행평가 등)은 분반(교과)별 운영 방향에 따라 자율적
```

**R30.** 허용 경고로 분류되는 폭 초과는 위 문단 **1건뿐**이다. 이 문단은 표 밖에 있고 그 컨테이너의 `lineWrap`이 `BREAK`라 한글이 파일을 열 때 다시 줄을 나눈다. 그 외의 폭 초과·겹침은 오류로 집계되어 FAIL이 된다 — 해당 문단은 실제로 겹칠 수 있으므로 고친다.

### 추가로 직접 확인할 것

**R31.** 표 안 비통일 charPr 0건 — `check_tpl2.py`가 자동 검사하므로 PASS면 충족된 것이다. 별도로 `restyle.py`가 `treatAsChar 해제 9건 / 라벨 셀 재작성 52건`처럼 0이 아닌 수를 보고했는지 확인한다.

**R32.** 고아 BinData 0건. **`check_tpl2.py` §5.6이 이 항목을 검사한다** — 고아가 남아 있으면 `[ERR]`로 집계되어 FAIL이므로, PASS를 받았다면 고아는 이미 0건이다. 검증기가 하지 않는 일은 **제거**다. 그래서 4단계의 제거 스크립트는 그대로 실행하고, 아래 명령은 5단계 전에 결과를 미리 보고 싶을 때 쓴다. §5.6은 세 가지를 각각 별도 `[ERR]`로 잡는다 — 고아(아무도 참조하지 않음) / 참조되나 매니페스트에 없음 / 매니페스트에 있으나 ZIP에 없음. 뒤의 둘은 그림 삽입이 깨진 경우이고 §5.5 그림 게이트도 함께 걸린다.
```bash
python3 -c "
import zipfile,re,sys
z=zipfile.ZipFile(sys.argv[1])
x=z.read('Contents/section0.xml').decode(); h=z.read('Contents/content.hpf').decode()
used=set(re.findall(r'binaryItemIDRef=\"([^\"]+)\"',x))
items=dict(re.findall(r'<opf:item id=\"([^\"]+)\" href=\"(BinData/[^\"]+)\"',h))
orphan={k:v for k,v in items.items() if k not in used}
missing=used-set(items)
print('고아', orphan)
print('참조되나 없음', missing)
print('BinData 검사:', 'OK' if not orphan and not missing else 'FAIL')" "출력파일.hwpx"
```
`고아 {}` · `참조되나 없음 set()` · `BinData 검사: OK` 세 줄이 다 나와야 한다. 값이 차 있으면 5단계 §5.6도 같은 것을 `[ERR]`로 잡아 FAIL이 되므로, 4단계로 돌아가 제거 스크립트를 다시 돌린다(`참조되나 없음`이면 그림 삽입이 깨진 것이므로 2단계부터 다시 한다).
