Codex 적대적 검증(필수 단계) 실행 방법과 프롬프트 틀.

## 왜 필수인가

이 스킬의 자체 검증 에이전트는 같은 모델이므로 **같은 맹점을 공유한다.** 실제로 이번 개발에서 자체 검증을 통과한 뒤 Codex가 잡아낸 결함이 여러 건 있었다. 대표적으로 파티팩의 인과 오류 — 문서가 "두께를 고정했기 때문에 넓이의 비만으로 한 변을 구할 수 있다"고 썼는데, 한 변은 두께와 무관하게 정해지고 두께 조건이 바꾸는 것은 부피였다. 자체 검증 두 겹이 이것을 놓쳤다.

## 실행

```bash
S=$(mktemp -d)          # 검토 자료와 결과를 둘 디렉터리 — 또는 작업 폴더 경로를 직접 지정
codex exec --skip-git-repo-check "<아래 프롬프트>" < /dev/null \
  > "$S/codex_review.md" 2> "$S/codex.err"
```

- `< /dev/null`을 빼면 **stdin을 기다리다 멈춘다.** 반드시 붙인다.
- 출력을 파일로 리다이렉트한다. `tail`로 일부만 보면 잘린다.
- `run_in_background: true`로 실행한다. ultra 효율에서 10분을 넘길 수 있다.
- 모델·추론 강도 플래그를 붙이지 않는다. `~/.codex/config.toml`에 최고 설정이 박혀 있다.

## 검토 자료 준비

Codex는 이 대화를 모른다. 슬롯 JSON을 그대로 주면 읽기 어려우므로 **섹션 구분자를 넣은 평문**으로 만들어 준다.

```python
# 사용법: python3 make_review_input.py <슬롯.json> <출력 디렉터리>
import json, sys

slot_path, S = sys.argv[1], sys.argv[2]
with open(slot_path, encoding="utf-8") as f:
    slots = json.load(f)

# "자료 전체"를 실제로 전체로 만든다 — 성취기준·성취수준·문항 유형·차시까지 전부.
# 둘째 성취기준을 쓰는 문항이면 std2_text·std2_A~std2_E도 추가한다.
order = ["task","purpose",
         "std1_text","std1_A","std1_B","std1_C","std1_D","std1_E",
         "item1_type","item1_form","item2_type","item2_form",
         "item3_type","item3_form","item4_type","item4_form",
         "item1_element","item2_element","item3_element","item4_element",
         "item_intro","item_questions","item_cond",
         "answer1","answer2","answer3","answer4",
         "rubric_rows","partial","caution",
         "level_A_score","level_A_desc","level_B_score","level_B_desc",
         "level_C_score","level_C_desc","level_D_score","level_D_desc",
         "level_E_score","level_E_desc",
         "lesson1_act","lesson1_eval","lesson2_act","lesson2_eval",
         "lesson3_act","lesson3_eval","lesson4_act","lesson4_eval",
         "lesson5_act","lesson5_eval"]
with open(S+"/review_input.txt","w",encoding="utf-8") as f:
    for k in order:
        v = slots.get(k, "")
        if k == "rubric_rows" and v:
            v = "\n".join(f"{r['item'].splitlines()[0]} | {r['elem']} | {r['score']}점 | {r['desc']}"
                          for r in v)
        elif isinstance(v, list):
            v = "\n".join(str(x) for x in v)
        f.write(f"\n===== [{k}] =====\n{v}\n")
```

## 프롬프트 틀

`<...>` 자리를 채워 한 덩어리 문자열로 넘긴다. 확정 수치를 반드시 인라인한다 — Codex가 독립 재계산할 기준값이 된다.

```
당신은 한국 <중학교|고등학교> 수학 서·논술형 평가 전문가다. 아래 파일은 <학년> <단원> <수행평가|지필평가>(<서술형 n문항+논술형 m문항>, 총 <총점>점) 자료 전체다: <review_input.txt 절대경로>
(섹션은 ===== [키] ===== 로 구분: 과제 개요, 출제 의도, 성취기준과 성취수준, 문항 유형·형식, 평가 요소, 문항 도입·자료, 발문, 조건, 예시답안, 채점기준표, 채점 시 유의점, 피드백 제공 시 유의점, 성취수준 점수 구간, 차시 계획·평가)
파일을 직접 읽고 다음을 검토하라.

[확정 수치]
<모든 확정 수치를 나열. 예: 지름 24/30/36cm, 두께 2/2.5/3cm, π=3.14, 1인분=미디엄 1/4판 부피, …>

[검토 관점]
1. 수학적 정확성 — 모든 수치를 직접 재계산해 검증하라. 오답 경로의 값까지 확인하라.
2. 채점기준의 급간 완결성 — 각 채점 요소의 급간이 상호 배타적이고 빈틈없는가. 두 급간에 동시에 걸리거나 어느 급간에도 안 걸리는 답안을 실제 시나리오로 구성해 시험하라. <평가 유형에 맞는 문장 하나만 남길 것 — 수행평가: "이 평가는 수행평가이므로 0점 급간이 없고 최저 1점 급간이 백지·완전 오답까지 포괄해야 한다. 요소 배점은 2~4점이고 1점 요소는 없어야 한다." / 지필평가: "이 평가는 지필평가이므로 각 요소에 0점 급간이 정확히 1건 있어야 하며, 그 진술은 글자·띄어쓰기·마침표까지 정확히 `무응답 또는 그 외의 오답.`이어야 한다(포괄만으로는 불충족 — 문자열이 다르면 결함으로 보고하라). 각 요소의 급간 점수는 배점 s부터 0까지 1씩 연속이어야 하고, 채점기준표 데이터 행 수 = Σ(요소 배점 + 1) = 총점 + 요소 수다. 지필평가에서는 1점 요소를 허용한다.">
   단, 학교 학업성적관리규정 오버라이드가 있으면 위 고정 문구·급간 수·최저 배점 대신 그 규정의 확정값으로 검사하라 — 규정이 0점 문구를 달리 정하면 그 문구가 고정 문구가 된다. <오버라이드 확정값 또는 `없음`>
3. 발문·조건·예시답안·채점기준·유의점·성취수준 구간의 상호 정합. 배점 표기가 모든 자리에서 일치하는가.
4. 성취기준 정렬 — 선언한 성취기준을 실제로 가르치고 평가하는가. 평가 요소와 무관한 요소가 채점기준에 들어 있는가.
5. <학교급> <학년> 수준 적정성 — 학년 범위를 벗어나는 개념이 필요해지는 지점이 있는가.
6. 제출용 완성도 — 남아 있는 개발 흔적, 군더더기, 어색한 문장.

[출력 형식] 심각도별로: (A) 치명 오류(수학·정합 파손) / (B) 개선 권고 / (C) 사소한 다듬기.
각 항목에 위치(섹션 키)와 그대로 붙여 쓸 수 있는 구체 수정안을 적어라. 문제없는 관점은 '이상 없음' 한 줄로. 한국어로.
```

## 결과 처리

1. 전문을 읽는다. 요약만 보고 판단하지 않는다.
2. **A급 지적은 반드시 반영한다.** 다만 반영 전에 원문을 직접 확인한다 — Codex가 파일의 다른 조항을 놓쳤을 수 있다.
3. B·C급은 적대적으로 재검증한 뒤 반영한다. 문서 구조를 바꾸는 권고(채점 요소를 더 잘게 쪼개라, 배점을 재배분하라, 평가 시간을 늘려라)는 **사용자 판단으로 남기고 보고만 한다.**
4. 반영 후 다시 빌드하고 검증기를 돌린다. 수정이 다른 곳을 깨뜨렸을 수 있다.
5. Codex 리뷰 전문을 위키나 산출물 폴더에 보존한다.

## 병렬 사용

독립된 대상이면 여러 Codex 호출을 **한 메시지에서 동시에** 띄운다(예: 제출용 세트와 추가 문항 세트를 각각). 각 호출은 자립적이어야 한다 — Codex는 호출 간 기억이 없으므로 필요한 경로·수치·형식 요구를 매번 인라인한다.

단, 하나의 검토 대상을 쪼개서 여러 번 부르지 않는다. 전체 정합을 봐야 하므로 한 번에 통째로 준다.
