채점기준표를 만들 때 따르는 규칙. 표 구조·배점 배분·급간 문장·배타성과 포괄성·채점 시 유의점, 그리고 마지막에 기계 검사 체크리스트.

이 문서만으로 끝나지 않는 것 — **성취기준 문구·성취수준 진술·성취수준 점수 구간**은 `references/standards.md`, **슬롯 JSON 전체 키와 조판 절차**는 `references/hwpx-build.md`를 읽고 한다. 이 문서는 `rubric_rows`(채점기준표 표 하나)만 다룬다.

## 1. 표 구조

### 열

| 열 | 내용 | 폭 비중 |
|---|---|---|
| 1 문항 | 문항 번호·성취기준 코드·평가 요소를 **세 줄**로 | 좁음 |
| 2 평가요소(채점요소) | 채점 요소 이름 하나 | 좁음 |
| 3 배점 | 급간 점수 하나. 숫자만 | 가장 좁음 |
| 4 수행 수준 | 급간 진술 한 문장 | 가장 넓음 |

경기 2025 자료집 원문은 `문항 | 평가 요소 | 채점 요소 | 배점 | 수행 수준(채점기준)`의 5열이다(`references/gyeonggi-2025-extract.txt` 3906행·4618행). 우리가 쓰는 서식은 4열이므로 **평가 요소를 문항 열의 셋째 줄로 접어 넣는다.** 5열 서식을 쓸 때에는 3줄 접기를 풀어 별도 열로 되돌린다.

### 행

- **급간 하나 = 표 한 행.** 한 셀에 여러 급간을 몰아넣지 않는다.
- 문항 열은 그 문항의 **모든** 급간 행에 세로 병합한다.
- 채점 요소 열은 그 요소의 급간 행에만 세로 병합한다.
- 마지막에 합계 행 1행.
- 데이터 행 수는 **평가 유형 프로파일(§2)** 에 따른다(§7 검사 6). 수행평가는 0점 급간이 없으므로 배점 s인 요소가 정확히 s행을, 지필평가는 0점 행이 하나 붙어 s+1행을 차지한다.

```
수행평가:  데이터 행 수 = Σ(요소 배점) = 총점
지필평가:  데이터 행 수 = Σ(요소 배점 + 1) = 총점 + 요소 수
표 전체 행 수 = 1(헤더) + 데이터 행 수 + 1(합계)
```

수행평가 20점 6요소 = 헤더 1 + 데이터 20 + 합계 1 = 22행, 15점 6요소 = 1 + 15 + 1 = 17행. 지필평가 20점 6요소 = 1 + (20+6) + 1 = 28행.

### 문항 열의 세 줄

```
문항 1
[9수03-12]
닮음비와 넓이·부피의 비 구하기
```

문항 번호 / 성취기준 코드 / 평가 요소 순서를 바꾸지 않는다. 채점기준을 읽는 자리에서 성취기준이 바로 보이게 하는 것이 목적이다. 성취기준이 두 개 이상 선언되어 있어도 **채점 대상으로 확정한 하나만** 적는다. 채점 대상이 아닌 성취기준을 여기 적으면 경기 자료집 일러두기("성취기준에 따른 성취수준과 관련 없는 요소들이 채점기준에 포함되지 않도록 주의")를 어긴다.

### 슬롯 JSON

빌더(`tools/build_tpl2.py`의 `build_rubric_v2()`)는 슬롯 JSON의 `rubric_rows` 키에서 아래 4키 딕셔너리의 리스트를 받아 연속 동일값을 rowSpan으로 묶는다. 따라서 **같은 문항·같은 요소의 행은 반드시 연속**해야 한다. `rubric_rows`를 쓰면 `rubric_n*`·`rubric_e*`·`rubric_p*`·`rubric_c*` 개별 키는 전부 버려진다(`references/hwpx-build.md` R6).

```json
{"item": "문항 1\n[9수03-12]\n닮음 판별하고 닮음비 구하기",
 "elem": "닮음 판별과 닮음비 구하기",
 "score": "4",
 "desc": "대응하는 모서리의 비, 라지팩까지의 닮음 판별, 닮음비를 모두 옳게 구함."}
```

`desc`는 §3 「급간 뼈대」의 개수 축으로 쓴다. 위 행은 원자 수행 3개(`모서리의 비`·`닮음 판별`·`닮음비`)를 최고 급간이 모두 열거한 4점 행이고, 같은 요소의 3·2·1점 행이 뒤에 이어진다.

합계 행:

```json
{"item": "합계", "elem": "—", "score": "20점",
 "desc": "문항 1부터 문항 4까지의 점수를 합하여 20점 만점으로 함."}
```

`score`는 문자열이지만 합계 행을 뺀 모든 행에서 `int()` 변환이 되어야 한다. 합계 행만 `"20점"`처럼 단위를 붙인다.

## 2. 배점 구조

배점 구조는 **평가 유형 프로파일**에 따라 갈린다(사용자 확정 정책). 기본값은 **수행평가**다. 이 구분은 연수 자료의 채점기준표 예시와 같다 — 수행평가 채점기준표 예시는 최저 급간이 1점이고, 정기시험 채점기준표 예시는 0점 급간(`무응답 또는 그 외의 오답.`)을 둔다. 어느 쪽이든 **학교 학업성적관리규정이 우선한다** — 규정이 다른 척도를 요구하면 규정을 따른다. **학교 규정이 기본 프로파일과 다르면 §7 검사 코드의 `SCHOOL_OVERRIDE`에 실제 값(최저 급간 `low`·요소 최소 배점 `min_element`·최저 급간 고정 진술 `zero_desc`)을 넣어 그 값으로 검사한다.** 행 수·floor·급간 수열은 프로파일 이름이 아니라 실제 적용값에서 나온다.

| 항목 | 수행평가(기본값) | 지필평가(정기고사) |
|---|---|---|
| 최저 급간 | 1점 | 0점 |
| 0점 진술 | 없음 | `무응답 또는 그 외의 오답.` (고정) |
| 요소 최소 배점 | 2점 | 1점 |
| 급간 점수열 | s, s−1, …, 2, 1 | s, s−1, …, 1, 0 |
| 요소 배점 s의 행 수 | s | s+1 |
| 제출자 최저 총점 | 요소 수 n | 0 |
| 성취수준 하한 처리 | 도달 가능 구간(n~총점) 재분할 | 0~총점 자연 분할 |

### 수행평가 프로파일 — 0점 급간을 두지 않는다

수행평가는 기본점수가 있어야 하므로 **최저 급간은 1점**이다. 연수 자료의 수행평가 채점기준표 예시도 최저 급간이 1점이다. 따라오는 결과는 §2 「성취수준 구간과 최저 총점」과 `references/standards.md` 4.2절 — 0점 급간을 **없앴기 때문에** 제출 답안의 최저 총점이 요소 수 n이 되고, 0~n−1점은 미응시·미제출 전용이 된다. 그래서 성취수준 구간을 도달 가능 점수(n~총점)로 재분할해야 한다. 최저 1점 급간이 백지·완전 오답까지 포괄한다(§4).

경기 2025 추출본에는 0점 급간이 있는 표와 없는 표가 혼재한다 — 0점 급간을 둔 표는 정기시험(지필) 형태이니(아래 지필 프로파일 소절), 추출본을 0점 없는 척도의 근거로 통째로 인용하지 말 것.

따라서 수행평가에서는:

```
요소 배점 s  →  급간 s단,  점수는 s, s−1, …, 2, 1
1점짜리 채점 요소는 존재할 수 없다(급간이 한 단뿐이라 척도가 아니다)
```

**1점 요소가 생기면 인접 요소와 통합한다.** v4(15점판)는 요소 9개가 모두 0점 급간을 달고 있었고, 그 가운데 **3개**가 최고 급간 1점이었다(`제곱·세제곱 관계 설명하기`·`페퍼로니 개수 구하기`·`공지문 조직하기`). 0점을 지우자 그 3개가 급간 1단이 되어 무너졌다. v5에서 요소를 6개로 통합해 해결했다(3/3/3/2/2/2 = 15점). 완성형 20점판의 실물은 동봉한 `examples/valid-similarity-20pt.json`의 `rubric_rows`에서 볼 수 있다. 그 파일의 급간 문장도 §3의 **개수 축으로 다시 쓴 확정본**이므로 배점 구조와 문언을 함께 본보기로 쓸 수 있다.

| v4 (0점 있음) | v5 (0점 없음) |
|---|---|
| 문항 1: `세 비 구하기` 2점 + `제곱·세제곱 관계 설명하기` 1점 | 문항 1: `세 비 구하고 관계 설명하기` 3점 |
| 문항 2: `페퍼로니 개수 구하기` 1점 + `㉡ 반박하기` 2점 | 문항 2: `개수 구하고 ㉡ 반박하기` 3점 |
| 문항 3: `두 단계 판단하기` 2 + `㉠ 반박하기` 2 + `공지문 조직하기` 1 | 문항 3: `방안 판단하고 공지문 쓰기` 3 + `㉠의 잘못 반박하기` 2 |

통합 방향은 **인지적으로 이어지는 것끼리**다. 판정 기준은 하나다 — **앞 요소가 산출한 값을 뒤 요소가 입력으로 쓰면 묶고, 쓰지 않으면 묶지 않는다.** `세 비 구하기` + `제곱·세제곱 관계 설명하기`는 설명이 앞의 세 비를 입력으로 쓰므로 묶어 `세 비 구하고 관계 설명하기`가 된다. 같은 문항이라도 입력·출력이 걸리지 않는 두 수행(`두 단계 판단하기`와 `㉠ 반박하기`)은 묶지 않고 따로 둔다.

### 지필평가(정기고사) 프로파일 — 0점 급간을 둔다

지필평가는 기본점수가 없으므로 **최저 급간은 0점**이다. 0점 급간의 진술은 요소와 무관하게 한 문장으로 고정한다.

```
무응답 또는 그 외의 오답.
```

- **1점짜리 채점 요소가 허용된다.** 0점 급간이 있으므로 1점 요소도 1/0 두 단이 성립해 척도가 된다. 수행평가의 "1점 요소 금지·인접 요소 통합" 규칙은 지필에는 적용하지 않는다.
- **행 수 공식이 바뀐다.** 요소마다 0점 행이 하나 늘어난다.

```
지필평가:  요소 배점 s  →  급간 s+1단,  점수는 s, s−1, …, 1, 0  →  표 s+1행
데이터 행 수 = Σ(요소 배점 + 1) = 총점 + 요소 수
```

- 근거 — 연수 자료의 정기시험 채점기준표 예시가 이 형태다. 경기 2025 추출본에도 0점 급간이 실재한다: `references/gyeonggi-2025-extract.txt`에 `무응답 또는 그 외(의) 오답` 꼴 0점 급간 행이 30개 있다(3912·4637·4645행 등, 3908~3938행·4620~4667행).
- 최저 총점이 0이므로 성취수준 구간은 **0~총점을 자연 분할**한다. 수행평가의 "도달 가능 구간 재분할"(아래 「성취수준 구간과 최저 총점」)이 필요 없고, 도달 불가 구간 문제도 생기지 않는다.

### 요소당 배점의 상하한

- 하한: 수행평가 2점(1점 금지), 지필평가 1점(1/0 두 단 성립).
- 상한 4점. 5단 이상 척도는 인접 급간을 말로 갈라내지 못한다.
- 문항 배점이 5점 이상이면 **요소를 두 개 이상으로 나눈다.**

### 총점별 권장 배분

문항 4개 기준. 괄호 안이 요소별 배점 = 급간 단수다.

| 총점 | 문항별 배점 | 요소 배점(급간 단수) | 요소 수 | 데이터 행 |
|---|---|---|---|---|
| 10 | 2 / 2 / 3 / 3 | 2 / 2 / 3 / 3 | 4 | 10 |
| 12 | 3 / 3 / 3 / 3 | 3 / 3 / 3 / 3 | 4 | 12 |
| **15** | **3 / 3 / 5 / 4** | **3 / 3 / 3+2 / 2+2** | **6** | **15** |
| 16 | 4 / 4 / 4 / 4 | 4 / 4 / 4 / 4 | 4 | 16 |
| **20** | **4 / 4 / 7 / 5** | **4 / 4 / 4+3 / 3+2** | **6** | **20** |
| 25 | 5 / 6 / 8 / 6 | 3+2 / 3+3 / 4+4 / 3+3 | 8 | 25 |
| 30 | 7 / 7 / 9 / 7 | 4+3 / 4+3 / 3+3+3 / 4+3 | 9 | 30 |

굵게 표시한 15점·20점이 실제로 조판·검증을 통과한 배분이다(v5·v6). 배점이 가장 큰 문항에 논술형을 배치하고, 그 문항만 요소를 3개까지 늘린다.

위 표는 수행평가 프로파일(요소 최소 2점) 기준이다. **지필평가는 1점 요소가 허용되므로 요소를 더 잘게 나눌 수 있다(예: 20점을 3+3+2+2+2+3+3+2, 8요소). 잘게 나눌수록 채점은 명료해지고 표는 길어진다**(지필 20점 8요소면 데이터 행 20+8=28).

### 성취수준 구간과 최저 총점

이 소절은 **수행평가 프로파일**의 것이다. 지필평가는 최저 총점이 0이므로 성취수준 구간을 0~총점으로 자연 분할하면 되고, 아래의 도달 불가 구간 문제가 생기지 않는다.

요소가 n개면 답안을 낸 학생의 **최저 총점은 n점**이다(모든 요소 1점). E 구간 상한을 n보다 작게 잡으면 E가 사실상 미응시 전용이 되어 도달 불가능한 구간이 된다.

```
E 구간 상한 ≥ 요소 수 n
```

이것은 필요조건일 뿐이다. **A~E 다섯 구간이 전부 도달 가능해야 한다** — 구간 나누기의 정식 절차(도달 가능 구간 n~총점을 다섯으로 나눈 뒤 E의 하한만 0으로 늘리기)와 검산 코드는 `references/standards.md` 4.2~4.3절에 있다. 총점·요소 수를 바꿨으면 그 절차를 다시 돌린다.

v6(20점·6요소)에서 A 19~20 / B 16~18 / C 8~15 / D 4~7 / E 0~3으로 두었다가 검증 지적을 받아, 추가문항은 A 18~20 / B 16~17 / C 10~15 / D 8~9 / E 0~7로 재분할했다.

## 3. 급간 진술 문체

### 형식 규칙

- **개조식 한 문장.** 마침표 1개. 종결은 **명사형 어미 ㅁ 받침** — `~함.` `~있음.` `~씀.` `~못함.` `~한다.` `~합니다.`로 쓰지 않는다. 기계 검사는 마지막 음절의 받침이 ㅁ인지로 판정한다(`(ord(ch) - 0xAC00) % 28 == 16`).
- **길이 25~45자, 50자 초과 금지.** 자수는 공백 포함 `len()`. 25자 미만과 45자 초과는 §7 검사 8이 경고만 내고 통과시키되 다시 줄여 볼 것, **50자 초과는 차단**이다.
  - v5 실측 27~46자(중앙 36자), v6 실측 27~42자(중앙 38자). v4는 최장 51자로 상한을 넘겼다.
- 하위 요건을 `⑴⑵⑶`으로 나열하지 않는다.
- `[채점 요소 N]`, `〈조 건〉③`, `원칙 6` 같은 **문서 내부 참조를 급간에 적지 않는다.**
- 마크다운 표기(`**`, `##`, `- `, `|`)를 넣지 않는다. HWPX에 그대로 인쇄된다.
- 인정 범위·동등 경로·수치 예시는 급간이 아니라 〈채점 시 유의점〉으로 뺀다(§6).
- **모호어를 쓰지 않는다.** `미흡`·`부족`·`다소`·`대체로`·`적절히`·`충분히`는 §7 검사 10이 차단한다(`references/hwpx-build.md` R15와 같은 목록). `알맞게`는 발문이나 〈조 건〉이 무엇이 알맞은지 이미 규정했을 때에만 쓴다(`문단마다 요구된 내용을 알맞게 배치함.`처럼 요구가 조건에 적혀 있는 경우). 규정이 없으면 관찰 대상을 수로 적는다.

### 급간 뼈대

**급간을 가르는 축은 요소마다 하나, `옳게 수행한 원자 수행의 개수`다.** 「수행의 완성도」와 「결과의 정오」는 급간을 가르는 축으로 쓰지 않는다 — 정오는 무엇을 셀지 정하는 기준으로만 들어가며, 세는 대상이 `옳게 수행한 것`이다. 그러므로 급간 문장을 쓰기 전에 **그 요소가 요구하는 원자 수행을 먼저 m개로 쪼개고**, 급간은 그 m개 가운데 몇 개를 옳게 했는지로만 가른다. **원자 수행**은 서로 독립적으로 옳고 그름을 판정할 수 있는 최소 수행이고, 요소 배점은 s로 적는다. 축을 이 하나로 고정하면 급간이 `옳게 수행한 개수` 0~m을 서로 겹치지 않는 구간으로 빠짐없이 덮으므로 겹침·공백이 원리상 생기지 않는다. 아래 뼈대의 `A`·`B`·`C`는 앞뒤 수행이 아니라 **원자 수행 하나씩**을 가리킨다.

#### 축을 고르는 규칙

1. **원자를 먼저 확정하고 이름의 자수를 예산으로 잡는다.** 급간 문장을 쓰기 전에 요소가 요구하는 원자 수행을 m개로 쪼개고 각각 짧은 이름을 붙인다. 하위 급간의 자수는 그 이름 합으로 정해진다.

   ```
   m=3 쉼표 나열   자수 = 이름 합 + 4  + 22     ← 쉼표·공백 2자 × 2, 꼬리 ' 가운데 한 가지도 옳게 수행하지 못함.'
   m=2 '와' 연결   자수 = 이름 합 + 2  + 22
   m=4 쉼표 나열   자수 = 이름 합 + 6  + 22
   ('옳게 구하지 못함'으로 끝내면 꼬리가 21자로 1자 짧다)
   ```

   지필평가는 최저 급간이 고정 진술이라 가장 긴 급간이 `… 가운데 한두 가지만 옳게 수행함.`(꼬리 19자)이므로 예산이 3자 늘어난다(m=4 이름 합 20자까지). 권장 상한 45자를 지키려면 수행평가 기준으로 이름 합이 m=3에서 19자, m=2에서 21자, m=4에서 17자 이하여야 한다. m=3에서 20자면 46자가 되어 넘는다(실측 — 이름 합 14자면 40자, 17자면 43자, 18자면 44자, 21자면 47자). 그래서 m이 클수록 이름을 짧게 잡는다(m=4는 이름마다 4자 안팎). **최고 급간은 이 예산에 매이지 않으므로 원자를 풀어 써도 되지만**(3단 3점 실제 문장의 `필요한 양의 충족에 따른 방안 선택`), 하위 급간에서는 같은 원자를 짧은 이름(`두 단계 판단`)으로 통일한다.

   **이름은 짧게 쓰되 판정 기준까지 줄이지는 않는다.** 급간에 인쇄되는 것은 원자의 *이름*이고, 그 원자를 옳다고 판정하는 *정의*는 따로 남긴다. **채점자용 원자 정의에는 「그 원자가 옳다고 판정되려면 무엇을 충족해야 하는가」를 적는다** — 요구된 값과 표기, 〈조 건〉이 지정한 필수 용어, `첫 문장에 결론을 밝힐 것` 같은 위치 지정, 설득해야 할 상대, 그리고 근거 없이 결론만 쓴 답안을 인정할지까지(§3 「백지·결론만 쓴 답안의 귀속」). 이 정의를 **슬롯 JSON의 `_rubric_atoms_note`나 〈채점 시 유의점〉에 반드시 남기고 급간 표와 함께 채점자에게 준다.** 동봉 예시 `examples/valid-similarity-20pt.json`이 요소마다 한 줄씩 적어 둔 형태가 본보기다. 정의 없이 이름만 배포하면 `넓이의 비` 다섯 글자 뒤에 공식·세 넓이·비 세 가지 산출이 숨고, 채점자마다 다른 것을 센다. 숨을 자리가 넓은 이름(`문단별 내용`)은 세는 범위를 정의에서 못 박는다 — 배치만 보는지 내용의 수학적 정오까지 보는지에 따라 다른 원자를 다시 세는 중복 감점이 된다.

   **역방향 대조는 필수 절차다.** §4 실패 사례 4의 대조가 「요구 → 원자」 한 방향이라면 여기서는 **두 방향을 모두 돌린다.** 발문·〈조 건〉의 요구를 동사 단위로 한 줄씩 적고 각 줄에 그것을 맡은 원자 이름을 적었을 때, **원자가 비는 줄이 하나라도 있으면 결함이다.** 실제로 자주 빠지는 자리는 셋이다 — 조건이 지정한 필수 용어(`지름·닮음비·넓이의 비를 쓸 것`), 문단 첫 문장의 내용 지정, 설득 대상(`누구의 어떤 주장에 답할 것인가`). 빠진 요구는 원자를 하나 더 만들거나(자수 예산을 다시 잡는다) 기존 원자의 정의에 판정 조건으로 넣어 채운다. 반대 방향에서 원자에는 있는데 발문·조건에 대응이 없으면 채점되지 않을 요구를 세는 것이므로 지운다. 이 대조표는 §7 수기 체크의 blocking 항목이다.
2. **원자 수 하한.** 수행평가는 m ≥ s−1, 지필평가는 m ≥ s. 수행평가 4점 요소는 원자 3개, 지필 4점 요소는 원자 4개 이상이 있어야 개수 0~m으로 급간 수만큼의 구간을 만들 수 있다. 미달이면 배점을 낮추거나 요소를 다시 나눈다.
3. **m ≥ 2이면 축은 언제나 개수다.** 예외를 두지 않는다.
4. **m = 1이면 개수 축이 두 급간밖에 만들지 못한다.** 수행평가는 2단만, 지필평가는 1점 요소만 허용한다. 그보다 큰 배점이 필요하면 앞 수행의 값을 뒤 수행이 입력으로 쓰는 인접 요소와 통합해 m을 늘린다(§2 「1점 요소가 생기면 인접 요소와 통합한다」와 같은 판정 기준).
5. **개수 배분.** 최고 급간은 m개, 최저 급간은 0개로 고정한다. 남은 급간이 1 ~ m−1을 나누고, 묶음 구간(`한두 가지`)은 가장 낮은 중간 급간에 하나만 둔다.
6. **어휘를 고정한다.** 모든 급간의 술어는 `옳게 수행함`과 `옳게 수행하지 못함` 한 쌍이다(요소에 따라 `옳게 구함`·`옳게 구하지 못함`처럼 동사만 바꾼다). `하였으나`·`일부만`·`일부 오류가 있음`·`시도하였으나`를 급간에 쓰지 않는다. 부분 인정과 연쇄 오류 구제는 〈채점 시 유의점〉으로 보낸다(§6).
7. **개수를 `만`과 `도`로 못 박는다.** `두 가지만`, `한 가지만`, `한 가지도 … 못함`으로 쓴다. `두 가지를`로 쓰면 `두 가지 이상`으로 읽혀 상위 급간과 겹친다 — 이 적대적 해석으로 4단(m=3) 8벡터를 전수 대입하면 8벡터 가운데 7벡터가 겹친다.
8. **최고 급간은 원자 m개를 모두 적고 `모두 옳게`가 그 전부를 한꺼번에 한정하게 쓴다.** `A를 구해 B를 하고 C를 옳게 구함`처럼 쓰면 `옳게`가 문법적으로 `구함`에만 붙어 앞의 두 원자는 "했다"까지만 요구된다고 읽히고, 두 개만 옳게 한 답안이 최고 급간과 그 아래 급간에 함께 걸린다. 원자마다 `옳게`를 붙여도 외연은 같다.
9. **2단의 최저 급간만 `이상`을 쓴다.** 2단은 최저 급간이 0개부터 m−1개까지를 함께 담아야 하므로 `한 가지 이상을 옳게 수행하지 못함`(= 최고 급간의 정확한 여집합)이다. 3단·4단의 `한 가지도 … 못함`을 2단에 복사하면 1개를 옳게 한 답안이 급간 밖으로 빠진다.
10. **원자는 서로 독립적으로 옳고 그름을 판정할 수 있어야 한다.** 앞 원자의 산출을 그대로 쓰는 뒤 원자는 독립이 아니므로, **의존 그래프를 적고 구제 규정을 두거나 원자를 다시 잡는다.** 개수 축은 겹침·공백을 막아 주지만 한 오류가 여러 원자를 무너뜨리는 것까지 막지는 못한다. 절차는 아래 「연쇄 구조와 후속 오류」에 있다.

#### 2단 (2점 요소 · 수행평가 · 원자 2개)

| 점수 | 뼈대 | 실제 문장 |
|---|---|---|
| 2 | A와 B를 모두 옳게 수행함. (16자) | 넓이의 비에서 거꾸로 구한 한 변과 두께 조건에 따른 부피 배수가 모두 옳음. (43자) |
| 1 | A와 B 가운데 한 가지 이상을 옳게 수행하지 못함. (29자) | 한 변 구하기와 부피 배수 구분하기 가운데 한 가지 이상을 옳게 수행하지 못함. (44자) |

원자가 3개인 2점 요소도 최저 급간 문언은 같다 — `한 가지 이상을 옳게 수행하지 못함`이 `모두 옳게 수행함`의 여집합이므로 m과 무관하다.

2단 최저 급간은 이접형으로도 쓸 수 있다. 외연이 같다.

```
A를 옳게 수행하지 못하거나 B를 옳게 수행하지 못함.            (30자)
파티팩의 한 변을 옳게 구하지 못하거나 부피 배수를 옳게 구분하지 못함.   (40자)
```

이접형을 쓸 때는 **두 이접지에 반드시 `옳게`를 넣는다.** `한 변을 구하지 못하거나`처럼 쓰면 착수 축이 되어, 틀리게라도 구한 답안이 어느 급간에도 걸리지 않는다.

원자가 4개(m=4)면 규칙 5대로 3점을 `A·B·C·D 가운데 세 가지만 옳게 수행함.`(25자), 2점을 `A·B·C·D 가운데 한두 가지만 옳게 수행함.`(26자)으로 쓴다.

#### 지필평가 (0점 프로파일 · 요소 배점 s · 원자 s개)

배점 3점 요소를 보기로 든다. 급간 점수와 `옳게 수행한 개수`가 그대로 맞물린다.

| 점수 | 뼈대 | 옳게 수행한 개수 |
|---|---|---|
| 3 | A·B·C를 모두 옳게 수행함. (17자) | 3개 |
| 2 | A·B·C 가운데 두 가지만 옳게 수행함. (23자) | 2개 |
| 1 | A·B·C 가운데 한 가지만 옳게 수행함. (23자) | 1개 |
| 0 | 무응답 또는 그 외의 오답. (15자, 고정) | 0개 |

2점 요소(원자 2개)는 2점 `A와 B를 모두 옳게 수행함.`(16자), 1점 `A와 B 가운데 한 가지만 옳게 수행함.`(22자), 0점 고정이다. 1점 요소(원자 1개)는 1점에 그 원자를 옳게 수행했다는 진술 하나(`A를 옳게 수행함.` 꼴, 원자 이름을 넣으면 25자 이상), 0점 고정이다. 원자가 배점보다 많으면(m > s) 규칙 5대로 남은 급간이 1 ~ m−1을 나눠 담는다.

0점 뼈대는 항상 `무응답 또는 그 외의 오답.` 한 문장이다 — 요소마다 바꿔 쓰지 않는다. **이 고정 진술의 `그 외의 오답`은 옳게 수행한 원자가 0개인 답안을 뜻한다.** 상위 급간에 걸린 답안은 여기에 걸리지 않는다. 개수 축을 쓰면 이 외연이 `0개`와 정확히 같아지므로, 잔여항 해석이나 판정 순서에 기대지 않고 문언만으로 배타성이 성립한다.

**지필평가에서도 `시도하였으나 옳게 해내지 못함` 꼴을 쓰지 않는다.** 이 진술은 옳게 수행한 원자가 1개 이상인 답안까지 함께 담아 상위 급간과 겹친다. 지필 최저 급간의 포괄은 고정 0점 진술이 맡는다. 따라서 §4 실패 사례 1의 시도 전제 금지는 **두 프로파일 모두에 적용한다.** 다만 §7 검사 11의 *부정 술어 필수* 조항은 수행평가 전용이다 — 지필 1점은 `한 가지만 옳게 수행함`이라는 긍정 진술이고, 부정 술어는 고정 0점 진술이 대신하지 않기 때문이다.

#### 백지·결론만 쓴 답안의 귀속 (두 프로파일 공통)

**결론만 쓴 답안의 귀속이 자동으로 정해진다.** 근거 없이 결론만 쓴 답안도 옳게 수행한 원자를 세면 되므로 요소마다 따로 확정할 필요가 없다. 결론이 원자 하나에 해당하고 그것이 옳으면 1개, 틀리면 0개다. 다만 **결론 하나를 원자 하나로 인정할지**(근거 없는 답만으로 `닮음비 구하기`를 옳게 수행한 것으로 볼지)는 원자를 정의하는 자리에서 못 박아 둔다. 그 정의가 곧 채점 판정이다.

```
수행평가  옳게 수행 0개 → 최저 1점 급간   (백지·전무 답안이 여기에 걸린다)
지필평가  옳게 수행 0개 → 고정 0점 급간   (백지·전무 답안이 여기에 걸린다)
결론만 쓴 답안 → 그 결론이 원자 하나를 옳게 수행한 것인지만 세면 된다
```

#### 접속형(연접·이접)은 더 이상 고르지 않는다

구 뼈대는 최저 급간을 연접(`~하지 못하고 ~도 하지 못함`)으로 쓸지 이접(`~하지 못하거나 ~하지 못함`)으로 쓸지를 바로 위 급간이 무엇을 담는지로 정하게 했는데, 그 짝짓기가 실제로 틀려서 4단에서 겹침이 났다(아래 「구 뼈대의 실물」). 개수 축에서는 최저 급간이 `한 가지도 옳게 수행하지 못함`(= 0개) 하나로 고정되므로 접속을 고를 자리가 없다. 예외는 2단 최저 급간의 이접형뿐이고, 그때에도 두 이접지에 `옳게`를 넣어야 한다.

#### 구 뼈대(v5·v6)의 실물 — 문체만 본보기로 쓰고 구조는 복제하지 않는다

아래는 v5·v6에서 실제로 쓰인 문장이고, 이 문서가 2026-08-01까지 표준 뼈대로 실어 두었던 것이다. 자수·개조식 문체·수치 배제는 지금도 본보기가 되지만 **급간 구조는 복제하지 않는다.** 각 원자를 전무·부분·완전 3상태로 부호화해 실현 가능한 9벡터를 전수 열거한 결과를 함께 적는다.

| 구 뼈대 | 실제 문장 | 전수 열거 결과 |
|---|---|---|
| 4단 2점 `A의 일부만 수행하거나 B를 하지 못함.` | 세 비를 구하는 과정의 일부만 수행하거나 관계를 설명하지 못함. | **겹침 1 · 공백 2.** 백지가 2점과 1점에 동시에 걸린다(둘째 이접지 `B를 하지 못함`이 백지에서 참이다). A를 전혀 하지 않고 B만 쓴 답안 두 갈래는 어느 급간에도 걸리지 않는다 |
| 3단 2점 `A는 하였으나 B에 일부 오류가 있음.` | 지름·넓이·부피의 비를 구하였으나 관계 설명에 일부 오류가 있음. | **공백 1.** A를 손대긴 했으나 틀리고 B는 옳게 한 답안이 3점·2점·1점 어디에도 걸리지 않는다 |
| 2단 1점 `A와 B 가운데 하나만 하거나 모두 하지 못함.` | 두 조건의 구분과 지름 구하기 가운데 하나만 하거나 모두 하지 못함. | **공백 3(문언 그대로 읽을 때).** 2점은 `옳게 수행`(정오 축), 1점은 `하다`(착수 축)로 축이 어긋나, 둘 다 손댔지만 하나 이상 틀린 답안이 빠진다 |
| 지필 1점 `A를 시도하였으나 옳게 해내지 못함.` | (v5·v6에 대응 실물이 없다. 이 문서 §3에만 있던 뼈대다) | **겹침 2.** 3단 상위 두 급간에 이어 붙이면 2점 상태(A를 하고 B에 부분 오류가 있는 답안 전부)를 통째로 포함한다 |

실물 파일 — 구 뼈대가 남아 있는 것은 `examples/examples-pizza.md` **A-6**뿐이다(같은 파일에 '결함·복제 금지'로 표시되어 있다). `examples/valid-similarity-20pt.json`의 `rubric_rows`와 같은 파일 **B-6은 개수 축으로 다시 쓴 확정본**이며, 둘 다 2ᵐ 전수 열거에서 겹침 0·공백 0을 확인했다. 새 표를 쓸 때는 이 둘을 본보기로 삼는다.

v6의 4점 요소는 원자가 2개(`세 비 구하기`·`관계 설명하기`)여서 규칙 2의 하한(수행평가 4점 → 원자 3개)에도 미달한다. B-6은 같은 요소를 원자 3개로 다시 쪼개어 이 하한을 맞췄다.

#### 연쇄 구조와 후속 오류

**원자 사이에 입력–출력 의존이 있으면 한 번의 오류가 여러 원자의 실패로 증폭된다.** 앞 원자가 산출한 값을 뒤 원자가 입력으로 쓰는 구조에서는, 앞에서 한 번 틀린 값을 그대로 이어 쓴 답안이 뒤 원자에서도 자동으로 틀린 것이 된다. 개수 축은 `옳게 수행한 개수` 0~m을 겹치지 않게·빠짐없이 덮으므로 **이것은 겹침·공백 문제가 아니다.** 깨지는 것은 **감점의 비례성**이다 — 한 번의 산술 오류가 개수를 여러 개 떨어뜨려 급간을 두 단 이상 끌어내린다.

동봉 예시 `examples/valid-similarity-20pt.json`의 문항 1이 실제로 이 구조다.

```
지름 자료               ─→ 지름의 비          (독립)
지름 자료               ─→ 넓이의 비 ─→ 부피의 비
지름의 비·넓이의 비·부피의 비 ─→ 관계 설명       (앞의 세 값을 모두 입력으로 쓴다)
```

넓이를 한 번 잘못 구하고 그 값을 부피와 관계 설명에 일관되게 이어 쓴 답안은, 결과의 정오만 보면 `지름의 비 1 / 넓이의 비 0 / 부피의 비 0 / 관계 설명 0` = 1개로 4점 만점에 **2점**이 된다. 처음 틀린 수행 하나만 미충족으로 세면 `1 / 0 / 1 / 1` = 3개로 **3점**이다. 같은 답안이 채점자에 따라 두 급간을 오간다. 문항 3의 `부피 산출·단위량당 값 → 두 단계 판단`, 문항 4의 `필요 부피 → 최소 판 수 → 총 개수`도 같은 사슬이다.

**규칙 — 원자를 확정할 때 의존 그래프를 함께 적는다.** 원자 이름을 세로로 늘어놓고 `앞 원자 ─→ 뒤 원자` 화살표를 그린다. 그래프는 원자 정의 옆(슬롯 JSON의 `_rubric_atoms_note`)에 남긴다. 화살표가 하나도 없으면 독립이므로 더 할 일이 없다. **화살표가 하나라도 있으면 〈채점 시 유의점〉에 같은 문항 안의 연쇄까지 포함하는 구제 규정을 반드시 둔다.** 붙여넣기 가능한 표준 문장은 다음과 같다.

```
앞 수행에서 잘못 구한 값을 그대로 이어 쓴 뒤 절차가 옳으면, 같은 문항 안이든 앞 문항에서
이어받았든 처음 틀린 수행 하나만 옳게 수행하지 못한 것으로 셈.
```

`앞 문항에서 잘못 구한 값을 이어받아…`로만 쓴 문장은 문항 **사이**의 연쇄만 구제하고 같은 문항 안의 `넓이의 비 → 부피의 비 → 관계 설명`은 구제하지 않는다. v6 실물이 이 형태였다(§6). 반드시 위 문장으로 바꿔 쓴다.

**한 문장·25~45자 제약은 급간 문장에만 적용된다.** 〈채점 시 유의점〉 문장은 그 제약을 받지 않으므로 길이를 줄이려고 `같은 문항 안이든`을 빼지 않는다. 다만 개조식과 명사형 어미(ㅁ 받침) 종결은 유의점에서도 지킨다(§6).

**연쇄가 강해 구제 규정으로도 비례성이 깨지면 원자를 다시 잡는다.** 구제 규정은 「처음 틀린 곳 하나만 센다」는 것이므로, 뒤 원자가 앞의 값 말고 **자기 몫의 수행**을 따로 가질 때에만 제구실을 한다. 사슬이 길거나(원자 셋 이상이 한 줄로 이어짐) 뒤 원자가 앞의 값을 옮겨 적는 것 말고 하는 일이 없어 구제 뒤에도 한 오류가 두 개 이상을 무너뜨리면, 다음 둘 가운데 하나를 한다.

- **원자를 독립적으로 다시 잡는다.** 사슬의 마디를 원자로 삼는 대신 **서로 다른 자료를 입력으로 쓰는 수행**을 원자로 삼는다. 문항 1이면 `넓이의 비`·`부피의 비` 대신 지름의 비만 입력으로 쓰는 `제곱 관계`·`세제곱 관계`로 갈라 잡을 수 있다. 이때 원자 정의에 「자신이 구한 수로 서술하면 앞의 값이 틀려도 옳게 수행한 것으로 봄」을 함께 적는다.
- **요소를 나눈다.** 사슬의 앞부분(산출)과 뒷부분(해석·설명)을 배점이 다른 두 채점 요소로 쪼갠다. 요소가 갈리면 앞 요소의 실패가 뒤 요소의 개수를 깎지 않는다. 다만 수행평가는 1점 요소를 만들 수 없으므로(§2) 양쪽이 모두 2점 이상으로 갈릴 때에만 쓴다.

§2 「통합 방향」이 **앞 요소의 산출을 뒤 요소가 입력으로 쓰면 묶는다**고 한 것과 부딪히는 것처럼 보이지만 층이 다르다. §2는 1점 요소를 없애려고 *요소*를 묶는 규칙이고, 여기는 묶은 뒤 그 안의 *원자*를 어떻게 세는가의 규칙이다. 묶어서 한 요소로 만들었으면 그 안의 연쇄는 구제 규정으로 처리하고, 구제로 모자랄 때에만 위의 두 대안으로 되돌아간다.

#### 검사

요소마다 원자 m개의 충족 여부를 0/1로 놓고 2ᵐ 벡터를 전수로 대입해, 각 벡터가 정확히 한 급간에만 걸리는지 python3로 판정한다. 절차와 코드는 §4 「검사 절차」에 있고, **이 전수 열거는 권고가 아니라 필수 절차다.** 백지 벡터(전부 0)가 최저 급간에, 만점 직전 벡터(하나만 0)가 만점 바로 아래 급간에 걸리는지를 반드시 포함한다. 겹침이 1건이라도 나오면 §4의 F01이며, 판정 순서를 근거로 덮어 두지 않는다.

개수 축을 쓰면 이 검사는 항상 통과한다 — 급간이 `옳게 수행한 개수`의 서로 겹치지 않는 구간으로 0부터 m까지를 빠짐없이 덮기 때문이다. 그래서 검사가 확인하는 것은 둘뿐이다. 급간에 배정한 개수 구간이 실제로 0~m을 빠짐없이 덮는가, 그리고 문언이 그 개수를 `만`·`도`로 못 박았는가.

```
✔ 제곱 관계, 치즈의 양, ㉡ 반박 가운데 두 가지만 옳게 수행함.                          (36자)
```

v6은 이 자리를 `세 비를 모두 옳게 구하였으나 그 관계를 설명하는 데 일부 오류가 있음.`(40자)으로 줄였다. 자수는 맞지만 `하였으나`·`일부 오류`가 축을 섞으므로 지금은 쓰지 않는다(규칙 6). 자수를 줄일 때 축까지 함께 보라는 뜻이다.

**축을 섞음 — 새로 추가한 항목**

```
✘ 세 비를 구하는 과정의 일부만 수행하거나 관계를 설명하지 못함.   (35자. 완성도 축 + 착수 축)
✔ 모서리의 비, 닮음 판별, 닮음비 가운데 한 가지만 옳게 수행함.    (36자. 개수 축 하나)
```

## 4. 배타성과 포괄성

정의는 두 줄이다.

- **배타성** — 어떤 답안도 두 급간에 동시에 걸리지 않는다.
- **포괄성** — 어떤 답안도 급간 밖으로 빠지지 않는다.

수행평가 프로파일은 0점 급간이 없으므로 **최저 1점 급간이 백지·완전 오답까지 포괄해야 한다.** 여기가 실제로 가장 자주 깨지는 자리다. 지필평가 프로파일은 고정 0점 급간(`무응답 또는 그 외의 오답.`)이 이 포괄을 맡는다 — 백지는 0점으로 간다(§3).

다만 **실패 사례 1의 시도 전제 금지는 두 프로파일 모두에 적용한다.** 지필의 1점을 `시도하였으나 옳게 해내지 못함`으로 쓰면 백지는 0점이 받아 주어 포괄성은 깨지지 않지만, 그 진술이 상위 급간의 상태를 통째로 삼켜 **배타성이 깨진다**(§3 「구 뼈대(v5·v6)의 실물」의 지필 1점 행, 겹침 2건). 포괄을 0점이 맡는다는 사실은 시도 전제를 정당화하지 않는다.

### 판정 순서 규칙 — 배타성의 대체물이 아니다

```
급간은 배점이 높은 쪽부터 아래로 대조하고, 처음 참이 되는 급간으로 판정한다.
다만 이 순서는 경계 답안을 확인하는 운영 절차일 뿐 문언상 겹침을 허용하는 규칙이 아니다.
한 답안이 두 급간 진술에 동시에 참이면, 높은 급간을 먼저 적용할 수 있더라도
F01 배타성 결함으로 판정하고 두 진술을 다시 쓴다.
```

**적용 순서는 운영 규칙일 뿐 배타성을 대체하지 않는다. 급간은 그 자체로 상호 배타적이어야 한다.** 높은 급간을 먼저 대조하면 최종 점수가 하나로 정해질 뿐, 두 술어가 동시에 참이라는 사실은 그대로 남는다. 그 사실이 남아 있는 한 F01 결함이며, 순서 규칙을 명시했다는 이유로 겹친 문언을 덮어 둘 수 없다.

순서 규칙 자체는 채점기준표 앞이나 〈채점 시 유의점〉에 명시한다. 명시하지 않으면 경계 답안에서 채점자마다 대조 순서가 달라진다. 다만 이 명시는 겹침의 해결이 아니라 겹침이 없는 표에 붙이는 운영 안내다 — 겹침은 아래 검사 절차와 실패 사례 3으로 찾아 진술을 고쳐서 없앤다.

### 검사 절차 — 2ⁿ 전수 열거가 필수다

**답안 몇 개를 골라 넣어 보는 것으로는 배타성·포괄성을 확정할 수 없다.** 요소마다 원자 수행 m개의 충족 여부를 0/1로 놓고 **2ᵐ 벡터를 전수로 대입해 각 벡터가 정확히 한 급간에만 걸리는지 python3로 판정한다.** 이 열거를 돌리지 않은 표는 조판으로 넘기지 않는다. 코드 아래의 네 답안 표는 열거 결과를 사람이 읽는 절차이지 열거를 대신하는 절차가 아니다.

1. **원자를 적는다.** §3 「축을 고르는 규칙」 1대로 요소가 요구하는 원자 수행 m개와 그 이름을 적는다. 원자를 못 적으면 급간을 쓸 수 없다.
2. **급간마다 걸리는 개수 집합을 적는다.** `4점 = {3개}`, `3점 = {2개}`, `2점 = {1개}`, `1점 = {0개}` 꼴로 **급간 문언에서 읽어 낸 그대로** 적는다. 문언에 `만`이 없어 `이상`으로도 읽히면 그 해석까지 따로 적어 두 번 돌린다(§3 규칙 7).
3. **2ᵐ 벡터를 돌린다.** 아래 코드를 스크래치패드에 저장하고 `BUCKETS`만 이번 요소의 값으로 바꿔 실행한다.
4. **결과를 읽는다.** 겹침 0 · 공백 0이어야 통과다. 백지 벡터(전부 0)가 최저 급간에, 만점 직전 벡터(하나만 0)가 만점 바로 아래 급간에 걸리는지도 함께 확인한다.

```python
# skel_enum.py — 급간 배타성·포괄성 2^m 전수 열거. 요소마다 한 번씩 돌린다.
from itertools import product

M = 3                                  # ← 이번 요소의 원자 수행 개수
NAMES = ["모서리의 비", "닮음 판별", "닮음비"]        # ← 원자 이름(보고용)
BUCKETS = [(4, {3}), (3, {2}), (2, {1}), (1, {0})]   # ← (급간 점수, 걸리는 '옳게 수행한 개수' 집합)
# 지필 3점 요소면 [(3,{3}), (2,{2}), (1,{1}), (0,{0})]
# 3단 원자 3개면  [(3,{3}), (2,{1,2}), (1,{0})]
# 2단 원자 2개면  [(2,{2}), (1,{0,1})]      ← 최저 급간이 0개와 1개를 함께 담는다

assert len(NAMES) == M
overlap = gap = 0
for v in product([0, 1], repeat=M):
    c = sum(v)
    hit = sorted([s for s, ks in BUCKETS if c in ks], reverse=True)
    mark = ""
    if len(hit) > 1: overlap += 1; mark = "  <== 겹침 F01"
    if not hit:      gap += 1;     mark = "  <== 공백"
    tag = " 백지" if c == 0 else (" 만점직전" if c == M - 1 else "")
    print(f"  {''.join(map(str, v))} 옳게수행 {c}개 -> {hit}{mark}{tag}")
print(f"겹침 {overlap}건 / 공백 {gap}건 — {'PASS' if not (overlap or gap) else 'FAIL: 급간 문언을 다시 쓴다'}")
```

전수 열거를 통과한 뒤, 아래 네 답안을 실제 문장으로 읽어 보아 벡터가 뜻대로 대응하는지 확인한다. 이것은 **열거 결과의 해석 점검**이다.

| 시험 답안 | 벡터 | 걸려야 하는 급간 |
|---|---|---|
| 백지(아무것도 쓰지 않음) | 전부 0 (옳게 수행 0개) | 수행평가 최저 1점 / 지필평가 0점 |
| 결론만 쓰고 근거가 전혀 없음 | 그 결론이 원자 하나를 옳게 채우면 1개, 아니면 0개 | 1개면 그 개수의 급간 / 0개면 최저 급간 |
| 원자 하나만 옳게 수행 | 하나만 1 | 개수 1개에 배정한 급간 |
| 하나를 뺀 나머지를 옳게 수행 | 하나만 0 (만점 직전) | 만점 바로 아래 급간 |

둘째 줄은 **원자를 정의할 때** 정해진다(§3 「백지·결론만 쓴 답안의 귀속」). 급간 문장을 고쳐서 정할 일이 아니라, `근거 없는 답만으로 이 원자를 옳게 수행한 것으로 볼지`를 원자 정의에 적어 두면 그대로 따라 나온다.

전수 열거에서 공백이 1건이라도 나오면 그 요소는 포괄성 결함이고, 겹침이 1건이라도 나오면 F01 배타성 결함이다. 어느 쪽도 판정 순서로 덮어 두지 않는다.

### 실패 사례 1 — 시도를 전제로 건 최저 급간 (차단 결함)

v5 검증에서 실제로 나온 결함이다(개발 기록 `wiki/피자문항/v5-v6-배점체계.md`에 `"밝히려 하였으나…"`, `"일부를 옳게 구하지 못함"`이 시도 전제 차단 결함으로 기록되어 있다. 아래 ✘는 그 기록에 남은 어절로 문장을 복원한 것이다).

```
✘ ㉠의 잘못을 밝히려 하였으나 옳게 반박하지 못함.
```

`밝히려 하였으나`가 **시도가 있었음을 전제**한다. ㉠에 대해 한 글자도 쓰지 않은 백지 답안은 "밝히려 하지도 않았으므로" 이 진술이 참이 되지 않는다. 그 위 2점 급간에도 걸리지 않는다. 0점 급간이 없으니 백지 답안에 줄 점수가 사라진다.

```
△ ㉠의 잘못을 밝히지 못하거나 옳게 반박하지 못함.        (27자, v5 확정본 — 구 뼈대)
✔ ㉠ 반박과 제안서 조직 가운데 한 가지도 옳게 수행하지 못함.   (34자, 개수 축)
```

v5 확정본(△)은 백지를 담는 데에는 성공했으나 첫 이접지가 `밝히지 못하거나`(착수 축), 둘째가 `옳게 반박하지 못함`(정오 축)이라 축이 어긋난다. 틀리게라도 밝힌 답안의 귀속이 문언으로 정해지지 않는다. 지금은 §3의 개수 축으로 쓴다.

**금지 표현** — 급간에 아래가 들어가면 무조건 차단이다(최저 급간은 물론 상위 급간에도 쓰지 않는다, §3 규칙 6). §7 검사 15가 기본값(`LEGACY_TABLE = False`)에서 이 차단을 집행한다.

```
~려 하였으나    ~하였으나    ~했지만    ~하려고 시도하였으나
~일부를 옳게 구하지 못함    ~구하는 과정에 오류가 있음    ~일부만 수행함
```

`~일부를 옳게 구하지 못함`도 같은 이유로 금지다. 일부라도 구한 답안을 전제하므로 아무것도 구하지 않은 답안이 빠진다. 최저 급간의 술어는 모두 `옳게 수행하지 못함 / 옳게 구하지 못함` 꼴이어야 한다 — 부정 술어이면서 동시에 **정오를 세는 기준**이 문장에 들어 있어야 한다. `하지 못함`만 쓰면 착수 축으로 읽혀 틀리게라도 한 답안이 빠진다.

### 실패 사례 2 — 이질적 결함을 "또는"으로 나열 (공백 결함)

v2 문항 2의 1점 급간이 아래 두 갈래였다.

```
✘ ① 라지 25개·자이언트 36개를 모두 구했지만 근거나 ㉡ 반박이 미흡함.
   ② 윗면 넓이 비례 원리와 ㉡ 오류 지점은 옳지만 개수 산출에 수학적 오류가 있음.
```

라지 25개를 **누락**한 답안(오류가 아니라 누락)은 ①에도 ②에도 들어가지 않는다. 원리와 오류 지점을 옳게 밝힌 상당한 수행인데 급간 밖으로 빠진다.

```
△ 페퍼로니 개수를 옳게 구하였으나 ㉡을 반박하는 데 일부 오류가 있음.   (v2 교정본 — 구 뼈대)
✔ 비례 원리, 개수 산출, ㉡ 반박 가운데 두 가지만 옳게 수행함.       (36자, 개수 축)
```

당시 교정본(△)은 두 갈래 나열을 한 문장으로 줄여 공백은 메웠지만 `하였으나`·`일부 오류`가 남아 축이 여전히 둘이었다. 원자를 셋으로 적고 개수로 가르면 나열도 축 혼용도 함께 사라진다.

**규칙** — 급간을 가르는 축은 요소마다 **하나**이고, 그 하나는 §3이 `옳게 수행한 원자 수행의 개수`로 고정했다. 축 후보가 셋이라는 옛 규칙은 폐기한다.

```
쓰는 축    ① 수행의 개수    — 요구된 원자 수행 가운데 몇 개를 옳게 했는가
안 쓰는 축  ② 수행의 완성도  — 다 했는가 / 일부만 했는가 / 못 했는가
안 쓰는 축  ③ 결과의 정오    — 값이 옳은가 / 일부 오류인가 / 틀렸는가
```

②와 ③을 축으로 쓰면 급간 사이에 부분 상태가 끼어들어 겹침·공백이 생긴다. ③의 정오는 축이 아니라 **무엇을 셀지 정하는 기준**으로만 남는다 — 세는 대상이 `옳게 수행한 원자`다. ②의 완성도는 급간에서 완전히 뺀다. 부분 인정이 필요하면 원자를 더 잘게 쪼개어 개수로 흡수하거나(§3 규칙 1), 〈채점 시 유의점〉으로 보낸다(§6).

검사 방법 — 한 요소의 급간 문장을 세로로 놓고 위에서 아래로 **변하는 말이 개수를 가리키는 어절 하나뿐인지** 본다. 개수 어절(`모두` / `두 가지만` / `한 가지만` / `한 가지도 … 못함`) 말고 다른 말이 함께 변하면 축이 섞인 것이다. 이 대조를 §7 검사 15는 어휘 수준에서, 검사 16은 원자 이름의 문자열 일치 수준에서만 걸러 주므로, 문장을 실제로 세로로 놓고 **뜻까지** 읽는 일은 수기로 한다.

### 실패 사례 3 — 같은 관찰 사실이 두 급간에 동시에 나타남 (중복 결함)

Codex 리뷰 A-1에서 확정된 결함이다. 1점 급간에 `또는 반박에 쓴 계산에 수학적 오류가 있음`이 있는데, 공통 원칙 6은 같은 요소에 대해 `원리 서술과 식이 옳으면 마지막 사칙연산 실수만으로 미충족 처리하지 않는다`고 정했다. 원리와 식은 옳고 마지막 계산만 틀린 답안이 2점이자 동시에 1점이 된다.

**규칙** — 급간 진술에 쓴 핵심어(`계산 오류`, `일부 오류`, `누락`)가 같은 요소의 두 급간에 동시에 나오면 안 된다. 구제 규정은 급간이 아니라 〈채점 시 유의점〉에만 둔다. §3의 개수 축을 지키면 이 핵심어들은 급간에 **한 번도** 나오지 않으므로 이 결함은 원리상 생기지 않는다. §7 검사 12는 구 뼈대로 쓴 표를 다시 검사할 때를 위해 남겨 둔 것이다.

### 실패 사례 4 — 조건이 요구한 것을 아무 급간도 관찰하지 않음

Codex A-3. 조건 ⑤가 문단별 내용 배치까지 지정했는데 급간은 "세 문단인가"만 관찰해서, 내용을 뒤섞어도 만점이 나왔다.

```
✘ 「주문 확정 공지문」을 세 문단으로 조직함.
△ 「주문 확정 공지문」을 세 문단으로 조직하고, 문단마다 요구된 내용을 알맞게 배치함.   (구 뼈대)
✔ 「주문 확정 공지문」의 세 문단 구성과 문단별 내용 배치가 모두 알맞음.            (40자)
```

△는 요구를 빠짐없이 관찰하는 데에는 성공했으나 `알맞게`가 문법적으로 `배치함`에만 붙어, 세 문단 구성 쪽에는 판정 기준이 걸리지 않는다(§3 규칙 8). `모두`가 두 원자를 한꺼번에 한정하게 고쳐 쓴다.

**규칙** — 발문과 〈조 건〉이 요구한 모든 수행은 어느 한 요소의 최고 급간에 반드시 대응어가 있어야 한다. 대응이 없는 요구는 채점되지 않는 요구다. 개수 축에서는 이 대조가 **원자 목록과의 대조**가 된다 — 요구 하나가 원자 하나에 대응하고, 최고 급간이 그 원자를 모두 열거한다.

검사 방법 — 표를 만든다. 왼쪽 열에 발문·조건에서 뽑은 요구를 **한 줄에 하나씩** 적고(동사 단위로 쪼갠다), 오른쪽 열에 그 요구를 맡은 **원자 수행의 이름과 그것이 실린 최고 급간의 어절을 그대로 옮겨 적는다.** 옮겨 적을 어절이 없으면 결함이다. `조건 ⑤ 문단마다 정해진 내용을 넣을 것` → 원자 `문단별 내용 배치` → 최고 급간의 `문단별 내용 배치가 모두 알맞음`처럼 짝이 눈에 보여야 한다.

## 5. 이름 규칙

### 채점 요소 이름 — 짧은 명사구 6~16자

명사형 `-기`로 끝낸다. §7 검사 14가 허용하는 어미는 **`하기`와 `쓰기` 둘뿐**이다(`공지문 쓰기`처럼 `쓰기`가 실제로 쓰인다). 다른 `-기` 어미를 쓰려면 검사 14의 허용 목록을 함께 늘린다. 배점을 이름에 넣지 않는다.

```
✔ 세 비 구하고 관계 설명하기 (15)    개수 정하고 ㉡ 반박하기 (13)
✔ 두 단계로 방안 판단하기 (13)      판 수와 총 개수 구하기 (13)
✔ 조건 구분하고 지름 구하기 (14)    ㉠ 반박하고 공지문 쓰기 (13)
```

```
✘ [채점 요소 1] 윗면 넓이·부피와 세 비의 산출 [2점]      (표기·배점이 들어감)
✘ 세 비 구하기 (7)                                  (통합 전 1점 요소의 잔재)
```

경기 자료집 실물도 대체로 이 폭이다: `조건 구하기`(6자), `가능성 설명하기`(8자), `적절한 정다각형 구하기`(12자), `원뿔 (가)의 반지름 구하기`(15자). 다만 `두 원뿔의 겉넓이와 부피 비교하여 설명하기`(23자, 4661~4667행)처럼 상한을 크게 넘는 것도 있다. 경기 실물을 상한의 근거로 삼지 말고 6~16자를 지킨다.

### 평가 요소 이름 — 10~17자

문항 열 셋째 줄에 들어간다. 성취기준을 그 문항에 맞게 구체화한 것이므로 채점 요소보다 넓다.

```
✔ 닮음비와 넓이·부피의 비 구하기 (17)    윗면 넓이의 비로 개수 정하기 (16)
✔ 주문 방안 판단하고 설득하기 (15)      판 수 구하고 새 규격 설계하기 (17)
```

```
✘ 닮음비와 넓이의 비·부피의 비 구하기 (20)   (v4. 20자로 표에서 세 줄로 접힘)
```

한 문항의 채점 요소를 모두 합치면 그 문항의 평가 요소가 되어야 한다. 실제 배점이 있는 수행이 평가 요소에 빠져 있으면 안 된다(Codex B-3: 문항 2의 `1개당 넓이 비교` 1점이 상위 평가 요소에 없었다).

## 6. 채점 시 유의점

**2~4문장.** 표 아래 별도 상자에 둔다. 채점기준표 안에 공통 행으로 넣지 않는다(같은 문장이 두 번 인쇄된다).

### 여기로 보내는 것

- 표현 방식의 다양성 인정
- 동등 경로·대체 표기(`aπ` 꼴과 3.14 병행)
- 사소한 수치 오차·반올림 자리 차이의 미감점
- 연쇄 오류 구제 — **같은 문항 안에서 앞 원자의 값을 이어 쓴 경우와 앞 문항의 틀린 값을 이어받은 경우 둘 다.** 원자에 의존 그래프의 화살표가 하나라도 있으면 필수다. 붙여넣을 표준 문장은 §3 「연쇄 구조와 후속 오류」에 있다
- 학년 수준 용어 고려

### 급간에 남기는 것

- 무엇을 옳게 수행했는지
- 어느 수행이 빠졌거나 오류인지
- 몇 가지를 수행했는지

### 여기로 보낼 수 없는 것 — 「조건 우선 규칙」

**학생 지면 〈조 건〉의 의무 조항을 유의점으로 되돌리지 않는다.** 유의점·부분 인정 기준·원자 정의·급간 진술이 〈조 건〉과 **같은 대상**에 서로 다른 처리를 지시하면 **〈조 건〉이 권위다.** 교사용 문서는 조건의 외연을 넓히지도 좁히지도 못한다 — 조건을 어긴 답안을 조건보다 관대하게 처리할 수 없고(관용 금지), 조건이 요구하지 않은 것으로 감점할 수도 없다(가중 금지). 조건은 학생에게 인쇄해 부과한 의무이고 유의점은 학생이 볼 수 없는 문서이므로, 학생이 예고받지 못한 것은 점수를 올리는 쪽으로도 내리는 쪽으로도 쓸 수 없다.

관대하게 채점할 의도라면 고칠 자리는 유의점이 아니라 **조건 자체다** — 그 항목을 〈조 건〉에서 빼 〈작성 도움〉·비채점 안내로 내리거나, 조건 문언을 관용 범위까지 넓혀 다시 쓴다. 학교 학업성적관리규정이 조건과 충돌하면 규정이 상위 권위이지만, 그때에도 고치는 자리는 조건이다.

```
✘ (조건 ②) 구한 값을 다시 계산에 쓸 때에는 반올림하기 전의 값을 쓸 것.
   (유의점)  반올림한 두 길이로 구한 0.4239도 옳게 구한 것으로 인정함.
             → 조건을 지킨 답안과 어긴 답안이 같은 점수를 받는다. 조건이 사문이 된다
✔ (유의점)  반올림 자리는 〈조 건〉②를 권위로 삼아, 마지막 자리의 0을 생략한 표기와
             지시된 자리보다 한 자리 더 나타낸 표기만 같은 값으로 인정함.
```

이 규칙의 결함 카탈로그·탐지 절차·F03·F06과의 경계는 `references/failure-modes.md` **F07**이 권위 본문이다. 유의점을 다 쓴 뒤 F07 [탐지 방법]으로 **조항마다 처리 절의 개수와 방향**을 세어 권위가 하나로 정해지는지 확인한다.

### 실물 (v6, 4문장)

```
학생의 표현 방식이 예시 답안과 다르더라도, 수와 식으로 나타낸 문제해결 과정이
수학적으로 논리적이면 점수를 부여할 수 있음.
넓이와 부피는 aπ 꼴로 나타낸 값과 원주율을 3.14로 보아 계산한 값을 모두 인정하며,
사소한 수치 오차나 반올림 자리의 차이는 감점 요인이 되지 않음.
앞 문항에서 잘못 구한 값을 이어받아 이후 절차를 옳게 수행한 경우에는 처음 틀린 곳에서
한 번만 감점함.
중학교 2학년 수준의 적절한 설명과 수학적 용어를 사용하였는지를 고려하여 채점함.
```

**셋째 문장은 그대로 복제하지 않는다.** `앞 문항에서`가 문항 **사이**의 연쇄만 구제해서, 같은 문항 안의 `넓이의 비 → 부피의 비 → 관계 설명` 사슬에서 한 오류가 세 원자를 무너뜨리는 것을 막지 못한다(§3 「연쇄 구조와 후속 오류」). 아래 표준 문장으로 바꿔 쓴다.

```
앞 수행에서 잘못 구한 값을 그대로 이어 쓴 뒤 절차가 옳으면, 같은 문항 안이든 앞 문항에서
이어받았든 처음 틀린 수행 하나만 옳게 수행하지 못한 것으로 셈.
```

문체는 `~함 / ~있음` 종결로 급간과 같게 맞춘다. `~한다`로 쓰지 않는다. 유의점 문장에는 급간의 25~45자 제약을 적용하지 않는다 — 구제 규정의 적용 범위를 자수 때문에 줄이지 않기 위해서다.

〈피드백 제공 시 유의점〉 상자가 따로 있으면 오답 유형별 처방을 그쪽에 쓴다. 채점 시 유의점에 처방을 섞지 않는다.

## 7. 기계 검사 체크리스트

`rubric_rows`(§1 슬롯 JSON)를 입력으로 아래를 전부 통과해야 조판으로 넘어간다.

**실행 방법**

1. 아래 코드를 스크래치패드에 `rubric_check.py`로 저장한다.
2. **`PROFILE`을 이번 평가 유형(`"수행평가"` | `"지필평가"`)으로, `ITEM`을 이번 문항의 배점으로, `CODES`를 0단계에서 받은 성취기준 코드로 바꾼다.** 아래 값은 피자 v6(수행평가, 4/4/7/5 = 20점, [9수03-12]) 전용이다. 이것을 고치지 않으면 검사 1·2·3·4·5·6·13이 틀린 기준으로 돈다.
   **학교 학업성적관리규정이 기본 프로파일과 다르면 `SCHOOL_OVERRIDE`에 실제 값을 넣는다**(§2). 모든 검사는 프로파일 이름이 아니라 `RULE`에서 파생한 실제 적용값 `LOW`·`MINS`·`ZERO_DESC`로 돈다. 예 — 학교 규정이 수행평가에도 0점 급간을 요구하면 `PROFILE = "수행평가"`를 그대로 두고 `SCHOOL_OVERRIDE = {"low": 0, "min_element": 1, "zero_desc": "무응답 또는 그 외의 오답."}`으로 검사한다.
3. 입력 파일은 최상위에 `rubric_rows` 키를 가진 슬롯 JSON이다(§1과 같은 4키 딕셔너리 리스트 + 합계 행 1개).
4. `python3 rubric_check.py <슬롯 JSON 경로> <총점>` — 종료 코드 0이면 통과, 1이면 조판 금지. `WARN` 줄(검사 8의 길이 권고)은 차단하지 않는다.
   **검사 15(뼈대 준수)와 검사 16(원자 정의 정합)의 위반은 기본값에서 차단이다.** 길이 권고와 뼈대 위반을 서로 다른 목록(`warn` / `skel`)으로 관리하고, `skel`은 `LEGACY_TABLE = False`인 한 `fail`로 합류해 종료 코드 1을 낸다.
   **`LEGACY_TABLE`은 이미 인쇄·배포된 구 뼈대 표를 서식만 바꿔 재조판할 때에만 `True`로 켠다.** 켜면 뼈대 위반이 경고로 낮아져 통과하고, 그 사실이 출력 첫 줄의 `LEGACY_TABLE=True — 구 뼈대 재조판 모드…` 알림과 마지막 줄의 `PASS — 수행평가+구뼈대재조판(…)` 표시로 **두 번 남는다.** 새로 쓰는 표에서 켜면 안 된다.
   `NOTE` 줄은 검사 16이 문장 구조를 읽지 못해 건너뛴 자리다. 차단하지도 경고로 세지도 않으니 그 요소만 수기로 세로 대조한다.
5. **이 스크립트는 배타성·포괄성을 판정하지 않는다.** 조판 전에 §4 「검사 절차」의 2ᵐ 전수 열거를 요소마다 따로 돌린다. 두 검사는 서로를 대신하지 못한다.

```python
# rubric_check.py — rubric_rows 전수 검사. 실패 1건이라도 있으면 조판 금지.
# 사용: python3 rubric_check.py slots.json 20
import json, re, sys
from collections import OrderedDict

rows  = json.load(open(sys.argv[1], encoding="utf-8"))["rubric_rows"]
TOTAL = int(sys.argv[2])                      # 총점
ITEM  = {"문항 1": 4, "문항 2": 4, "문항 3": 7, "문항 4": 5}   # ← 매번 이번 문항 배점으로 교체
CODES = {"[9수03-12]"}                        # ← 매번 0단계에서 받은 성취기준 코드로 교체(대괄호 포함, 문자열 그대로)

# 평가 유형 기본 프로파일(§2). 학교 학업성적관리규정이 다르면 규정이 우선한다.
DEFAULT_RULES = {
    "수행평가": {
        "low": 1,                             # 최저 급간
        "min_element": 2,                     # 요소 최소 배점
        "zero_desc": None,                    # 최저 급간 고정 진술(없으면 None)
    },
    "지필평가": {
        "low": 0,
        "min_element": 1,
        "zero_desc": "무응답 또는 그 외의 오답.",
    },
}

PROFILE = "수행평가"       # 문서에 표시할 평가 유형
SCHOOL_OVERRIDE = {}       # 학교 규정이 다를 때만 채움
# 예: {"low": 0, "min_element": 1,
#      "zero_desc": "무응답 또는 그 외의 오답."}

# 구 뼈대 재조판 스위치. 새로 쓰는 표에서는 반드시 False로 둔다.
#   False(기본) — 검사 15·16의 뼈대 위반을 fail로 올려 조판을 차단한다.
#   True        — 이미 인쇄·배포된 구 뼈대 표를 서식만 바꿔 재조판할 때만. 뼈대 위반을 경고로
#                 낮춰 통과시키고, 그 사실을 출력 첫 줄 알림과 마지막 줄 TAG에 남긴다.
LEGACY_TABLE = False

assert PROFILE in DEFAULT_RULES
assert set(SCHOOL_OVERRIDE) <= set(DEFAULT_RULES[PROFILE]), \
    f"SCHOOL_OVERRIDE 키 오타: {set(SCHOOL_OVERRIDE) - set(DEFAULT_RULES[PROFILE])}"
RULE = {**DEFAULT_RULES[PROFILE], **SCHOOL_OVERRIDE}

LOW = int(RULE["low"])                        # 실제 적용 최저 급간
MINS = int(RULE["min_element"])               # 실제 적용 요소 최소 배점
ZERO_DESC = RULE.get("zero_desc")             # 최저 급간 고정 진술. None이면 최저 급간이 백지를 포괄해야 함
TAG = (PROFILE + ("+학교규정" if SCHOOL_OVERRIDE else "")
       + ("+구뼈대재조판" if LEGACY_TABLE else ""))       # 실제 적용 근거를 출력에 남긴다
fail, warn = [], []                           # fail은 조판 차단, warn은 길이 권고 등 보고만
skel, note = [], []                           # skel은 뼈대 위반(검사 15·16), note는 검사 16이 건너뛴 자리

data  = [r for r in rows if r["item"] != "합계"]
tot   = [r for r in rows if r["item"] == "합계"]

# 1. 요소별 급간 = 배점부터 실제 적용 최저 급간(LOW)까지 1씩 하강하는 연속 수열
el = OrderedDict()
for r in data:
    el.setdefault((r["item"].split("\n")[0], r["elem"]), []).append(int(r["score"]))
for k, v in el.items():

# 16. 원자 정의 정합 — 급간 문장에서 원자 이름 목록을 뽑아 요소 안에서 세로로 대조한다.
#
#     [한계 — 이 검사가 판정할 수 있는 것과 없는 것]
#     이름의 '문자열 일치'와 '개수'만 본다. 다음 셋은 원리상 판정하지 못하므로 §7 끝의

#       · 그 이름이 가리키는 수행이 발문·〈조 건〉의 요구를 빠짐없이 덮는가(역방향 대조, §3 규칙 1)
#       · 짧은 이름 뒤에 여러 산출이 숨지 않는가(채점자용 원자 정의, §3 규칙 1)
#       · 원자가 서로 독립인가, 연쇄가 있으면 구제 규정을 두었는가(§3 「연쇄 구조와 후속 오류」)
#     문장 구조를 읽지 못해 아래 셋은 건너뛰고 NOTE로 남긴다(그 요소는 수기 대조 대상).
#       · `가운데`·`모두` 어느 것도 없는 급간 — 구 뼈대 문장이라 애초에 원자 목록이 없다
#       · 구분자가 섞인 목록(`A·B와 C`) — `·`가 이름 사이인지 이름 안인지 가를 수 없다
#       · 2단 최저 급간의 이접형(`A를 옳게 …하지 못하거나 B를 옳게 …하지 못함`, §3 규칙 9) —
#         정상 문형인데 원자 목록 어형이 아니다. NOTE가 떠도 고칠 것이 없다
#     최고 급간이 원자를 풀어 써도(`대응하는 모서리의 비` ↔ `모서리의 비`, §3 규칙 1) 이름이
#     아니라 개수만 대조하므로 걸리지 않는다. 별칭의 동치는 원자 정의가 선언해야 한다.
NUM = {"한": 1, "두": 2, "세": 3, "네": 4, "다섯": 5, "여섯": 6, "일곱": 7}

def atom_list(desc):
    """급간 문장에서 원자 이름 목록을 뽑는다 → (목록, 건너뛴 사유). 못 뽑으면 (None, 사유)."""
    m = re.match(r"^(.+?)\s*가운데\s", desc) or re.match(r"^(.+?)[을를이가]\s*모두\s", desc)
    if not m:
        return None, "원자 목록 어형 없음"
    s = m.group(1).strip()
    kinds = [d for d in ("·", ",") if d in s] + (["와과"] if re.search(r"[와과]\s", s) else [])
    if len(kinds) > 1:
        return None, "구분자 혼용"
    parts = re.split(r"·|,|[와과]\s", s) if kinds else [s]
    return [p.strip() for p in parts if p.strip()], ""

for k in el:

            top_n = len(lst)
        else:
            lists.setdefault(tuple(lst), []).append(int(r["score"]))
    # (가) 세로 대조 — 하위 급간은 같은 원자를 같은 이름으로 반복해야 한다(§3 규칙 1)
    if len(lists) > 1:
        shown = " ≠ ".join("[" + "·".join(t) + "]" for t in lists)
        skel.append(f"16 하위 급간의 원자 이름이 서로 다름 — 한 이름으로 통일할 것 {k}: {shown}")
    m_low = len(next(iter(lists))) if len(lists) == 1 else None
    # (나) 최고 급간이 하위 급간과 같은 수의 원자를 열거하는가(이름은 풀어 써도 된다)
    if m_low and top_n and top_n != m_low:
        skel.append(f"16 최고 급간 원자 {top_n}개 ≠ 하위 급간 원자 {m_low}개 {k}: {top['desc']}")
    # (다) 중간 급간의 개수 표현이 원자 수와 맞는가 — `n 가지만`은 1 ≤ n ≤ m−1이어야 한다
    m_atom = m_low or top_n
    if m_atom:
        for r in rs:
            mm = re.search(r"가운데\s*(한두|한|두|세|네|다섯|여섯|일곱)\s*가지(?![도])(?!\s*이상)",
                           r["desc"])
            if not mm:
                continue                       # `한 가지도 … 못함`(0개)과 2단 `한 가지 이상`은 제외
            n = 2 if mm.group(1) == "한두" else NUM[mm.group(1)]
            if not 1 <= n <= m_atom - 1:
                skel.append(f"16 '{mm.group(1)} 가지만'이 원자 {m_atom}개와 맞지 않음 "
                            f"{k}: {r['desc']}")

# 제출자 최저 총점(floor) — 프로파일 이름이 아니라 실제 요소별 최저 급간의 합.
# 성취수준 A~E 재분할은 이 값으로 한다(references/standards.md §4.2~4.3).
submitted_floor = sum(min(v) for v in el.values())

# 뼈대 위반(검사 15·16)의 처분 — 기본은 차단, LEGACY_TABLE을 켠 실행만 경고로 낮춘다.
if LEGACY_TABLE:
    print(f"LEGACY_TABLE=True — 구 뼈대 재조판 모드로 실행함. "
          f"검사 15·16 뼈대 위반 {len(skel)}건을 차단하지 않고 경고로 낮춤.")
    warn += skel
else:
    fail += skel

for x in note:
    print("NOTE " + x)
for w in warn:
    print("WARN " + w)
print("\n".join(fail) if fail
      else f"PASS — {TAG}(최저 {LOW}점) / 요소 {len(el)}개 / 데이터 {len(data)}행 / "
           f"총점 {TOTAL}점 / 제출자 최저 총점 floor={submitted_floor} / 경고 {len(warn)}건")
sys.exit(1 if fail else 0)
```

**정규식이 판정할 수 없는 것을 먼저 적는다.** 검사 8~15는 자수·문체·어휘만 본다. **급간이 배타적·포괄적인지는 어떤 정규식으로도 판정할 수 없다** — 그것은 문장의 외연을 비교하는 일이고, 그 일을 하는 절차는 §4의 2ᵐ 전수 열거뿐이다. 아래 첫 두 줄은 권고가 아니라 blocking이며, 위 스크립트가 PASS를 찍었다는 사실로 대신하지 않는다.

```
□ (blocking) 요소마다 원자 수행 m개를 적고 2ᵐ 벡터를 전수로 대입해 겹침 0·공백 0을 확인했는가
  §4 「검사 절차」의 skel_enum.py를 요소 수만큼 돌린 출력이 있어야 한다.
  급간에 배정한 개수 집합이 0~m을 빠짐없이·겹치지 않게 덮는지를 눈이 아니라 코드로 본다
□ (blocking) 급간 문장을 세로로 놓았을 때 변하는 말이 개수 어절 하나뿐인가
  (`모두` / `두 가지만` / `한 가지만` / `한 가지도 … 못함` 말고 다른 말이 함께 변하면 축이 섞인 것)
  검사 15는 알려진 어휘만, 검사 16은 이름의 문자열 일치만 거른다. 새로 지어낸 표현으로 축을 섞으면 차단이 걸리지 않는다
□ 최고 급간이 원자 m개를 모두 열거하고, `모두 옳게`가 그 전부를 한꺼번에 한정하는가
  (`A를 구해 B를 하고 C를 옳게 구함`처럼 마지막 원자에만 걸리면 아래 급간과 겹친다)
□ 백지 답안을 요소마다 넣어 보아 전부 최저 급간(수행평가 1점, 지필평가 0점)에 걸리는가
□ (수행평가) 각 1점 진술에 실제 백지·완전 오답을 대입했을 때 진술이 참인가
  (단순히 부정 술어가 있다는 이유만으로 통과시키지 않는다)
  ※ 이 줄은 권고가 아니라 blocking이다. 검사 11의 ATTEMPT는 어형만 보는 정규식이라
    `구한 뒤`·`얻은 값으로`처럼 어미를 피한 시도 전제는 통과시킨다. 검사 11이 PASS여도
    이 대입을 실제로 해 보기 전에는 1점 급간의 포괄성을 확정하지 않는다
□ 결론만 쓰고 근거가 없는 답안이 원자 하나를 옳게 채운 것으로 볼지가 원자 정의에 적혀 있는가
  (급간 문장이 아니라 원자 정의에서 정해진다, §3)
□ (blocking) 원자마다 **채점자용 정의**(옳다고 판정되려면 무엇을 충족해야 하는가)를 적어
  슬롯 JSON `_rubric_atoms_note`나 〈채점 시 유의점〉에 남기고 채점자에게 급간 표와 함께 주는가
  검사 16은 이름의 문자열 일치만 본다. 짧은 이름 뒤에 여러 산출이 숨었는지는 정의를 읽어야 안다
□ (blocking) **역방향 대조** — 발문·〈조 건〉의 요구를 한 줄씩 적고 맡은 원자 이름을 적었을 때
```

**검사 15·16의 뼈대 위반이 뜬 표는 조판으로 넘어가지 못한다.** 기본값 `LEGACY_TABLE = False`에서 위반은 `fail`로 합류해 종료 코드 1을 내므로, 조판 절차가 종료 코드만 보아도 걸러진다. 예전처럼 경고를 띄우고 종료 코드 0으로 통과시키지 않는다 — 그 구현은 §4가 `무조건 차단`이라고 규정한 축 혼용을 코드가 집행하지 않는 상태였다.

**예외는 하나다 — 이미 인쇄·배포된 구 뼈대 표를 서식만 바꿔 재조판하는 경우.** 그때만 `LEGACY_TABLE = True`로 켠다. 켠 실행은 출력에 두 번 남는다.

```
LEGACY_TABLE=True — 구 뼈대 재조판 모드로 실행함. 검사 15·16 뼈대 위반 3건을 차단하지 않고 경고로 낮춤.
WARN 15 축 혼용 어휘 — §3 개수 축으로 다시 쓸 것: …
PASS — 수행평가+구뼈대재조판(최저 1점) / 요소 6개 / … / 경고 3건
```

새로 쓰는 표에서는 켜지 않는다. 스위치는 **다시 쓰기 싫을 때**가 아니라 **다시 쓸 수 없는 배포본일 때**의 것이다. 동봉 예시 `examples/valid-similarity-20pt.json`은 개수 축으로 다시 써서 위반 0건이므로 이 예외에 해당하지 않는다. 어느 모드에서도 §4의 2ᵐ 전수 열거와 위 수기 세로 대조는 그대로 한다 — 스위치는 어휘·이름 검사만 낮추고 배타성·포괄성 판정에는 관여하지 않는다.
