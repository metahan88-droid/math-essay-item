# 서·논술형 수학 문항 개발

성취기준에서 출발해 **문항 초안 → 채점 요소 → 급간별 수행 수준 → HWPX 조판**까지 완성한다.

## 반드시 지키는 것

1. **채점기준 문체는 개조식이 기본이다.** 급간 진술은 한 문장 25~45자, 50자 초과 금지. 하위 요건을 ⑴⑵⑶으로 나열하지 않는다. 인정 범위·동등 경로·수치 예시는 급간이 아니라 〈채점 시 유의점〉으로 뺀다.
2. **0점 처리는 평가 유형을 따른다.** 수행평가는 기본점수가 있어야 하므로 0점 급간을 두지 않는다 — 최저 급간은 1점이고 그 급간이 백지·완전 오답까지 포괄하며, 따라서 모든 채점 요소는 2점 이상이어야 한다. 지필평가(정기고사)는 0점 급간을 두며 최저 급간 진술은 "무응답 또는 그 외의 오답."으로 고정하고, 1점짜리 채점 요소도 허용한다. 기본값은 수행평가다. (사용자 확정 정책이다. 외부 표준이 아니라 사용자 결정이며, 학교 학업성적관리규정이 다르면 규정을 따른다 — 0단계에서 확인한다.)
3. **초안은 반드시 수치 검산을 통과해야 한다.** 초안 에이전트가 python3로 전수 재계산하고 학년 범위 위반을 자체 검사한다. 검산 없이 나온 초안은 채택하지 않는다.
4. **전이성 5요건을 모두 갖춘다.** 새 맥락 / 관계 도출 / 오개념 진단 / 다중 경로 / 역방향 추론. 하나라도 빠지면 초안을 되돌린다. (이 스킬의 확정 기본 정책이다. 외부 표준이 아니라 사용자 결정이며, 학교 규정·평가 목적이 다르면 0단계에서 조정한다.)
5. **검증은 세 겹이다.** 급간 게이트(적대적 검증 에이전트) + 어긋남 리뷰어(정합성) + **Codex 적대적 검증(필수)**. 셋을 다 통과해야 조판으로 넘어간다.
6. **성취기준·성취수준은 NCIC 공시 자료를 근거로 한다.** 지어내지 않는다. 선언한 성취기준은 반드시 가르치고 평가한다.

## 절차

### 0단계 — 입력 받기 (사용자에게 묻는다)

AskUserQuestion으로 **한 번에** 묻는다. 추측해서 진행하지 않는다.

- **성취기준** — 코드와 문구(예: `[9수03-12] 도형의 닮음의 뜻과 닮은 도형의 성질을 이해하고, 닮음비를 구할 수 있다.`). 여러 개면 그중 **채점 대상 하나**를 확정한다.
- **평가 요소** — 성취기준을 문항에 맞게 구체화한 것. 사용자가 정하지 못하면 성취기준에서 후보 3개를 뽑아 고르게 한다.
- **총점과 문항 수** — 기본값 20점 4문항(4/4/7/5). 15점이면 3/3/5/4.
- **학교급·학년·과목**, **평가 시간**, **소재 선호**.
- **평가 실시 연도와 적용 교육과정** — 2022 개정은 중1·고1 2025년, 중2·고2 2026년, 중3·고3 2027년부터 적용된다. 실시 연도와 학년에 따라 2015/2022 자료를 고른다.
- **평가 유형** — 수행평가(기본값) 또는 지필평가(정기고사). 0점 급간 정책이 여기서 갈린다(원칙 2).
- **학교 학업성적관리규정의 0점·기본점수·미응시 처리 정책** — 규정이 평가 유형 프로파일과 다르면 규정이 우선한다.
- **문항 수** — 현재 서식·도구는 4문항 전용이다. 다른 수를 원하면 조판 없이 텍스트 산출까지만 지원함을 알려라.

사용자가 이미 초안 느낌을 제시했다면 1단계의 후보 생성을 **그 방향으로 제한**한다.

### 1단계 — 초안 3개 병렬 생성 + 수치 검산 + 심사

Workflow로 실행한다. `workflows/develop-draft.js`를 상황에 맞게 고쳐 쓴다.

- 초안 에이전트 3개를 **서로 다른 소재 각도**로 병렬 생성(예: 구매·의사결정 / 설계·제작 / 검수·판별).
- 각 에이전트는 초안 안에서 **python3로 전 수치를 재계산**하고, 학년 범위 위반(무리수·세제곱근·미학습 개념)과 값이 유한소수로 떨어지는지를 자체 검사한 결과를 함께 반환한다. 검산에 실패하면 스스로 수치를 고쳐 다시 계산한다.
- 심사 에이전트가 전이성 5요건 충족도·수치 견고성·채점 가능성으로 세 초안을 평가해 순위와 개선점을 낸다.

### 2단계 — 사용자가 고르고 다듬는다

세 초안의 **요약·수치 설계·전이성 판정·심사 의견**을 표로 제시하고 AskUserQuestion으로 고르게 한다. 사용자가 수정 방향을 주면 반영해 확정 초안을 만든다.

### 3단계 — 채점 요소와 급간 작성

`references/rubric-rules.md`를 읽고 작성한다. 급간 구조는 0단계에서 정한 평가 유형 프로파일을 따른다(references/rubric-rules.md §2).

- 채점 요소는 평가 요소를 관찰 가능한 수행으로 쪼갠 것. 짧은 명사구 6~16자.
- 급간은 배점부터 프로파일의 최저 급간(수행평가 1점·모든 요소 2점 이상 / 지필평가 0점·1점 요소 허용)까지 1씩 하강한다. **급간을 가르는 축·원자 수행의 개수·문장 뼈대·어휘는 요약하지 말고 `references/rubric-rules.md` §3 「급간 뼈대」를 그대로 따른다**(배점은 원자 수 하한에 매이므로 원자를 먼저 확정한다).
- `rubric_rows` 형식으로 만든다. `item` 필드에 문항 번호·성취기준 코드·평가 요소를 세 줄로 넣어 **채점기준과 성취기준을 연결**한다.
- 예시 답안, 〈채점 시 유의점〉(2~4문장), 성취수준 A~E 구간을 함께 만든다.

채점기준만이 아니라 **완성 슬롯 JSON 전체를 조립**해야 조판이 된다. 발문·자료(`item_intro`/`item_questions`/`item_cond`), 예시답안(`answer_n*`/`answer*`), 과제 개요(`task`)·출제 의도(`purpose`), 문항 정보(`item*_type`/`form`/`element`), 차시(`lesson*`), 성취수준(`level_*`), 유의점(`partial`/`caution`)까지 스스로 채운다. 키 목록과 형식은 `references/hwpx-build.md`의 슬롯 표를 따르고, `examples/valid-similarity-20pt.json`을 형식 견본으로 쓴다.

### 4단계 — 검증 세 겹 (전부 필수)

**(a) 급간 게이트** — 적대적 검증 에이전트. `workflows/verify-rubric.js`를 상황에 맞게 고쳐 실행한다. `references/failure-modes.md`의 프롬프트 문구를 **조판 전 모드(시험 1~11)**로 쓴다 — 시험 12(F22)는 .hwpx가 생기는 6단계 뒤에 돌린다. **두 급간에 동시에 걸리는 답안 시나리오와 어느 급간에도 안 걸리는 답안 시나리오를 직접 구성해 시험**하게 한다.

**(b) 어긋남 리뷰어** — 정합성 검증 에이전트. (a)와 마찬가지로 `workflows/verify-rubric.js`를 상황에 맞게 고쳐 실행한다. 발문·조건·예시답안·채점기준·유의점·성취수준 구간의 상호 참조와 배점 표기를 전수 대조한다. 총점을 바꿨다면 발문 배점·도입부 총점·차시 평가란·성취수준 구간이 함께 바뀌었는지 반드시 확인한다.

**(c) Codex 적대적 검증** — 필수. 백그라운드로 실행한다. OUT은 이 작업의 스크래치 폴더다(예: `OUT=$(mktemp -d)`).

```bash
OUT="${OUT:-$(mktemp -d)}"
codex exec --skip-git-repo-check "<자립적 프롬프트>" < /dev/null > "$OUT/codex_review.md" 2>"$OUT/codex.err"
```

`< /dev/null`을 빼면 stdin을 기다리다 멈춘다. Codex는 이 대화를 모르므로 프롬프트에 검토 대상 파일 경로·확정 수치·검토 관점(수학적 정확성 전수 재계산 / 발문·조건·답안·채점기준 정합 / 급간 완결성 / 문체)과 출력 형식(A 치명 / B 권고 / C 사소, 위치와 구체 수정안)을 인라인한다.

지적은 **적대적으로 재검증한 뒤** 반영한다. 확정된 것만 고치고, 구조를 바꾸는 권고는 사용자 판단으로 남긴다.

### 5단계 — 자료 그림 만들기

`references/figures.md`를 읽고 만든다. 판단 규칙은 하나다 — **그림 안의 글자가 문항 내용이면 직접 작도하고, 아니면 gpt-image-2에 맡긴다.**

- 가격표·안내판·쪽지·대화방·실측 도해·크기 비교도·모눈 탐구는 **예외 없이 `tools/figlib.py`로 직접 작도**한다. AI 이미지 모델은 한글을 뭉개고, 자료의 글자가 틀리면 문항이 무너진다.
- 분위기·맥락 삽화만 `gpt-image-2` 스킬로 만든다. 프롬프트에 한글을 넣지 말고 `no text, no letters, no numbers`를 명시한다.
- **정답을 그림에 흘리지 않는다.** 학생이 구할 값은 `"?"`로 둔다.
- 만든 그림은 **모두 Read로 열어 확인한다.** AI 생성물은 반드시 본다.
- 슬롯 JSON에 `_figs` 매핑을 넣는다. 경로는 슬롯 JSON이 있는 폴더 기준이다.
- **출력 폴더를 먼저 정한다.** `figlib.OUT`의 기본값은 `FIGLIB_OUT` 환경변수이고, 없으면 **현재 작업 디렉터리 기준 `./figs`**다. 스킬 폴더 안에 쌓이지 않는다. 작업 폴더에서 `python3 "<스킬>/tools/figlib.py"`로 데모를 돌려도 **스킬 폴더는 오염되지 않고 산출물은 작업 폴더에 생긴다.** `figs/`는 슬롯 JSON 옆에 둔다.
- 그림보다 조판을 먼저 보고 싶으면 6단계를 `--draft`로 한 번 돌린다(아래). 그때도 `_figs`는 미리 다 적어 둔다.

### 6단계 — HWPX 조판

`references/hwpx-build.md`를 읽고 실행한다. 슬롯 JSON 작성 → `build_tpl2.py` → `restyle.py` → `check_tpl2.py` 검증. **세 단계뿐이다** — 미참조 BinData는 빌더가 애초에 넣지 않는다.

```bash
WORK=<작업폴더>; S=<스킬>; cd "$WORK"
# 빌드 — 기본이 최종 모드다. _figs의 PNG가 하나라도 없으면 FileNotFoundError로 중단한다.
python3 "$S/tools/build_tpl2.py" "$WORK/out.hwpx" "$WORK/content.json"
# 그림을 만들기 전에 조판만 미리 보려면 초안 모드(플래그는 두 위치 인자 뒤에만)
python3 "$S/tools/build_tpl2.py" "$WORK/out.hwpx" "$WORK/content.json" --draft
python3 "$S/tools/restyle.py"    "$WORK/out.hwpx"
python3 "$S/tools/check_tpl2.py" "$WORK/out.hwpx" "$WORK/content.json"
```

- **최종 모드가 기본, `--draft`가 초안 모드다.** 최종 모드는 `_figs`가 가리키는 PNG가 없으면 빌드를 중단해 그림 빠진 최종본이 나가는 것을 막는다. 초안 모드는 그 줄을 자리표시 텍스트로 남기고 계속한다. **제출본은 반드시 플래그 없이 다시 빌드한다.**
- **고아 BinData 제거 단계는 없어졌다.** 빌더가 서식의 미참조 이미지를 산출물에서 빼고(`미참조 BinData 제외:` 줄로 알린다), `check_tpl2.py` **§5.6 BinData 정합**이 고아·참조 누락·매니페스트 밖 파일·중복 등록·손상 PNG를 오류로 잡는다. 검증 출력의 `고아 0건 / 참조 누락 0건`을 확인한다.
- 통과 기준: 내용 누락 0, 셀 주소 중복 0, 표내 비통일 charPr 0, SQUEEZE 다중줄 0, XML 정상, **BinData 고아 0**. `check_tpl2.py`가 `PASS`를 찍어야 한다.

조판이 끝나면 `references/failure-modes.md`의 시험 12(F22)를 **조판 후 모드**로 실행해 산출물을 최종 감사한다.

## 작업 원칙

- **되먹임을 허용한다.** 채점 요소를 짜다 발문이 부족하면 발문을 고친다. 배점을 바꾸면 발문 배점·총점 표기·성취수준 구간을 **같이** 고친다. 앞 단계를 고쳤으면 뒤 단계를 다시 확인한다.
- **자기 보고를 믿지 않는다.** 작성 에이전트는 매번 "전 항목 통과"라고 말한다. 실제 결함은 전부 적대적 검증에서 나왔다.
- **수치는 항상 python3로 재계산한다.** 눈으로 확인하지 않는다.
- 중간 산출물은 스크래치패드에 JSON으로 저장하고, 완성본은 사용자 프로젝트 폴더에 버전 접미사(`_v2`, `_v3`)를 붙여 쓴다.
